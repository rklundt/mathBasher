## Design review (Story 1)

The draft design was checked against the code by the full review panel (architecture, senior dev, DevOps, InfoSec, legal, support). All six asked for changes and none for a redesign; the design below includes them. Where the panel disagreed, the choice is noted.

Main corrections to the draft:

- The Math-a-lotl decision needed a cleaner shape (one `kind`, no second "next" field), escapes passed in with their answer, and more test rows.
- The Climb hint flag is session-only, so it can be renamed after all.
- The asteroids are tagged `particle`, not `alien`.
- The footer's path is referenced in more places than listed.

## Design

### D1. Shared callouts — `src/game/ui/callouts.ts`

**API** (Phaser; one module):

| Helper | What it does | Options (all values come from config) |
|---|---|---|
| `createTapHint(scene, opts)` → `{ show(), destroy() }` | Pulsing "👆 …" pill. | `x`, `y`, `label`, `height`, `backdropAlpha`, `width?` (default: text width + padding), `fixedToCamera?` |
| `floatNote(scene, x, y, msg, opts)` | Rises and fades with the `Quad.In` ease. | `risePx`, `durationMs`, `edgeMarginPx?` — clamps x only when given |
| `fadeNote(scene, x, y, msg, opts)` | Holds, then fades with the default ease; doesn't move. | `holdMs`, `fadeMs` |
| `screenBanner(scene, msg, opts)` → `Text` | Centred banner; returns the text so callers can restyle it (Frog Splash's finish banner does). | `style?` (typography key), `fixedToCamera?` |
| `applyBannerLegibility(text)` | The heavy stroke + shadow every banner uses. | — |

**`destroy()`:**
- Safe to call twice (a tap and a key press can both dismiss the hint).
- It kills the pulse tween before destroying the pill.
- The helper adds **no** shutdown listener. Phaser's tween manager and display list already clean up on scene shutdown, and each scene builds its hint again in `create`. A comment says so, so nobody adds one later.

**Shared look:**
- Numbers go into `config.layout.callout`:
  - pill padding 48
  - border 2 px at 0.7 alpha
  - depth 50 for hints, 100 for notes and banners
  - stroke 6 for notes, 8 for banners
  - shadow offset 3, blur 6
  - pulse 800 ms to alpha 0.6, `Sine.InOut`
- Colours go into `uiPalette.ts`: the ink `0x0b1020` / `'#0b1020'` and the white border.

**Per-game values** move from scene literals into each game's config block:

| Game | Hint position | Size | Backdrop alpha | Fixed to camera |
|---|---|---|---|---|
| Frog Splash | y 150 | 60 tall | 0.55 | yes |
| Math-a-lotl | waterline + 70 | 240 × 64 | 0.5 | no |
| Space Shooter | height − 62 | 60 tall | 0.75 | no |

**Pure placement math, with tests:**
- `calloutGeometry.ts`: the generic edge clamp (`clampNoteX`).
- `mathALotlMath.ts`: Math-a-lotl's own "below the bubble unless that leaves the screen" rule, beside its other tested helpers.

**Adopted by:**
- Frog Splash, Math-a-lotl and Space Shooter (all helpers).
- Number Climb: `applyBannerLegibility` only. Its hint and win banner aren't centred screen banners; "Out of time!" may use `screenBanner`.
- Asteroid Field: its "Out of shots!" banner uses `screenBanner` (added in the pre-release review). Not adopted: its aim hint (a different design: icon + label, blue outline). Alien Shoot has none.

### D2. Math-a-lotl outcome as a pure function

`resolveBubbleEvent(state, event)` in `src/game/systems/mathALotlMath.ts` follows `resolveRungPick` (`numberClimbFloorMath.ts`) and uses `resolveStrike` (`roundRules.ts`). As built it has three typed overloads (`CatchDecision`, `EscapeDecision`, `TimeoutDecision`), so each switch in the scene only lists the outcomes that event can produce. The tap-hint options shipped as `heightPx` / `widthPx`.

- **State:** `{ correctAnswer, livesUsed, maxLives, usedWrongCatch }`.
- **Event:** `{ type: 'catch', answer }` | `{ type: 'escaped', answer }` | `{ type: 'timeout' }`.
- **Decision.** A union keyed by `kind`, which is the only thing that says what happens next; there's no second "next" field to drift:

| Kind | Carries | Meaning |
|---|---|---|
| `correct` | `record` | Recorded with `usedWrongShot` = flag. |
| `wrong` | `livesUsed`, `livesRemaining`, `usedWrongCatch: true` | Same wave continues. |
| `out-of-lives` | `livesUsed`, `livesRemaining: 0`, `record { wasCorrect: false, usedWrongShot: true }` | Round ends. |
| `escaped-correct` | — | No record, flag kept; the wave respawns. |
| `escaped-wrong` | — | Ignored; the bubble just pops. Today the scene makes this check itself. |
| `timeout` | `record { wasCorrect: false, usedWrongShot: flag }` | No life lost. |

**The scene keeps:**
- **Side effects:** sound, tweens, shake, HUD events, telemetry.
- **Guards:** `transitioning`, `roundOver`, and the timeout → catch → escape order in `update`.
- **Single fire:** `QuestionClock` guarantees the timeout fires only once.
- **Clock:**
  - correct and out-of-lives stop it
  - a wrong catch leaves it running
  - an escape freezes it while the wave respawns
- **Flag reset:** `usedWrongCatch` resets in `startNextQuestion`.

The scene switches on `kind`, with an `assertNever` default.

`out-of-lives` behaves the same as today:
- It first runs every wrong-catch effect: sound, `popWrong`, shake, `strikesChanged`, `WrongCatch` telemetry.
- It shows **no** "Oops" note.
- It emits `questionEnded` without `QuestionEnded` telemetry or advancing the question index.

**Tests:**

| # | Situation | Expected |
|---|---|---|
| 1 | Correct, first try | `correct`, `usedWrongShot` false, no life lost |
| 2 | Correct after a wrong catch | `correct`, `usedWrongShot` true (half points), no life lost |
| 3 | First wrong catch (0 → 1 of 3) | `wrong`, 2 left |
| 4 | Second wrong catch (1 → 2 of 3) | `wrong`, 1 left |
| 5 | Wrong on the last life (2 → 3 of 3) | `out-of-lives`, record `{false, true}` |
| 6 | `maxLives = 1`, first wrong catch | `out-of-lives` |
| 7 | Right bubble escaped, flag false / true | `escaped-correct`, flag unchanged |
| 8 | Wrong bubble escaped | `escaped-wrong` |
| 9 | Timeout, flag false | `timeout`, record `{false, false}`, no life lost |
| 10 | Timeout, flag true | `timeout`, record `{false, true}` |

`assertNever` is a new `src/shared/assertNever.ts`. It sits at the bottom layer, so the app and the server can both use it. (The panel suggested `src/shared` and `src/core`; `shared` sits below `core`, so it serves both.)

Frog Splash and Space Shooter have the same shape. They're on the backlog as a follow-up.

### D3. Number Climb wording ("mulligan" → wrong pick / life lost)

Every wrong pick now costs a life, so "mulligan" (a free retry) misleads. About 51 lines across 11 files.

**Renamed:**

| From | To |
|---|---|
| `'wrong-mulligan'` (the `RungPickKind` union and the `RungPickOutcome` variant) | `'wrong'` (matches D2, and `resolveRungPick` doesn't know about lives) |
| `handleWrongMulligan` | `handleWrongPick` |
| `hasUsedMulligan()` | `hadWrongPickThisFloor()` (it only drives half points) |
| `usedMulligan` (local) | `hadWrongPick` |
| the `wrongPickedMulligan(rung)` doc | the new name |
| `maybeShowFirstMulliganHint` | `maybeShowFirstLifeLostHint` |
| `MULLIGAN_HINT_HOLD_MS` / `_Y_FRAC` and the 300 ms fade | `config.numberClimb.lifeLostHint { holdMs, yFrac, fadeMs }` (magic numbers today) |
| the session flag `numberClimb.mulliganHintSeen` | `numberClimb.lifeLostHintSeen` |

The session flag is in `sessionStorage`, not saved settings, so the worst case is one extra "Lost a life!" hint mid-session at deploy time. That's why it's renamed rather than kept.

Comments change to match in `config.ts`, `HudScene.ts`, `typography.ts`, `NumberClimbHero.ts`, `NumberClimbRung.ts`, `NumberClimbInputSystem.ts` and `ScoreCalculator.test.ts`, and so does `docs/SCORING.md`.

**Kept, with a comment marking them as legacy:**
- The telemetry event `NumberClimb.wrongMulligan`.
- The `usedMulligan=` text in the `NumberClimb.correctPick` reason.

Renaming either would split existing reports. `VERSIONS.md` history isn't edited.

**Also:** an `assertNever` default on `NumberClimbScene.handlePick` and on the `NumberClimbFloorSystem` outcome switch (backlog). The `heroRestY` test stays deferred; it is still a one-line formula.

### D5. Asteroid sprite kind

The eight Asteroid Field rocks are tagged `kind: 'particle'` in the manifest. They were only *processed* with the alien profile, and their URL is the one hard-coded path in the manifest.

**New `asteroid` kind:**
- a `process.mjs` profile (same as the 192 px alien profile), plus its header's kind list
- `KIND_FOLDER.asteroid = 'asteroids'`
- the same entry in `extract-from-video.mjs`'s `KIND_FOLDERS`, the third "keep in sync" spot
- `SpriteKind` and `WEBP_KINDS` entries
- the manifest URL through `spritePath('asteroid', key)`

**Moving the files:**
- `git mv` the eight `aliens/asteroid-N.webp` files to `asteroids/`, byte-identical.
- Update the eight paths in `CREDITS.md` and the comments in `spriteKeys.ts`.

**Tests:** a `spritePath('asteroid', …)` assertion, and a check that every asteroid file exists on disk, to catch a botched move.

**Notes:**
- **Cache.** The new folder means new URLs, and the existing `/assets/sprites/*` rule already covers it, so there's no config change and no stale art.
- **Open tabs.** A tab left open across the deploy could 404 on the old path when entering Asteroid Field. The image rocks are on by default but lazy-loaded when that game starts, and load errors are already reported. Acceptable.
- **Telemetry.** The boot telemetry's per-kind sprite counts shift: 8 entries move from `particle` to `asteroid`.
