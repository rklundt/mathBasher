## Summary

Clean-up work with no gameplay change: shared helpers for code now copied across games, a tested outcome function for Math-a-lotl, small naming and folder fixes, and the repo and process pieces that make outside contributions and local checks possible.

The sprint opens with an assessment and peer review (Story 1). It confirms the design for every item, finalizes the stories below, and stops for the project owner's approval before any code changes.

## Stories

### Story 1: Assessment + peer review (design gate)
Survey the current code for each item and draft a design. Run the review panel (architecture, senior dev, DevOps, InfoSec, legal, support) on the **plan**, not on code, then fold their findings back in. Questions to settle:

- **Shared tap hint + pop-up messages.**
  - Frog Splash, Math-a-lotl and Space Shooter each have `buildTapHint` / `hideTapHint` (Math-a-lotl also has `showTapHint`) and their own pop-up / toast code. Decide one helper API in `src/game/ui/`: what's shared and what stays per game (position, timing, "remove once used").
  - Decide whether Asteroid Field, Number Climb and Alien Shoot adopt it now or later.
- **Math-a-lotl outcome logic.**
  - Today the right catch / wrong catch / escaped bubble / timeout handling lives in `MathALotlScene`; only the geometry helpers in `mathALotlMath.ts` are tested.
  - Define a pure `resolve…` function (inputs, outputs, how it uses the shared `roundRules`) and its test table.
  - Check whether Frog Splash or Space Shooter should follow the same pattern; that could be a later sprint.
- **Number Climb "mulligan" wording** (34 mentions in `src/`, plus `docs/SCORING.md`).
  - Choose the new term, matching the "lives" wording the other games use.
  - Decide what must *not* change: the persisted settings / score keys, and the telemetry event name `NumberClimb.wrongMulligan`. Renaming it breaks continuity in reports, so either keep it or note the rename in the telemetry plan.
- **Footer code.** `src/game/ui/domAttributionFooter.ts` is DOM code, not Phaser. Pick its home under the folder-discipline ADR (ADR-0006), keeping the AGPL §7(b) attribution and the §13 source link untouched.
- **Asteroid sprite kind.**
  - The asteroids use the `alien` kind; give them their own `asteroid` kind (sprite-pipeline profile + folder).
  - Shipped assets are cached for a week, so any moved or changed file needs a new filename. Confirm whether this moves files or only renames the kind.
- **Contribution files.**
  - `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md` exist. Contributions are "not yet open" because the dual license needs a CLA mechanism first.
  - Recommend CLA Assistant, DCO sign-off or a signed file (legal review; confirm with counsel).
  - The owner decides whether contributions **open** this sprint or the mechanism is just made ready.
  - Shape the PR and issue templates (bug, idea; security issues routed to SECURITY.md).
- **Local checks.**
  - ESLint (flat config) + Prettier: rule set, and how to land a repo-wide format without burying history (one format-only commit + `.git-blame-ignore-revs`).
  - Pre-commit hook (lint, typecheck, leak scan). Pick the tool; the dev drive is exFAT with no symlinks, so prefer a `core.hooksPath` folder or a tool that doesn't need symlinks. Keep the hook fast: typecheck may belong in CI only.
  - The leak scanner's word list can't be committed (it *is* the vocabulary it hunts), so decide how a committed hook calls a local-only scanner and skips cleanly when it's absent.
  - `.nvmrc` (Node 22).
  - Add `pnpm lint` to the required CI check.
- **GitHub repo description + topics.** These are public, so draft them and the owner approves the wording.

**Output:** this file updated with the agreed design and the final stories, plus any ADR the design calls for. **Gate:** the project owner approves before Story 2 starts.
