## Summary

A new math type — **"Add Fractions"** — available in all three game modes. It is the project's first generator that breaks two long-standing assumptions, which is why it earns its own sprint rather than a single story in 2.2.1:

1. **Non-integer answers.** Every existing generator produces integer answers and the whole stack assumes it — `Question.correctAnswer: number`, `Question.choices: number[]`, and the answer-rendering in all three games shows the bare number. A fraction answer (`3/8`, `1 1/2`, `4`) cannot ship as a bare `number`; `0.375` is wrong for a kids' math game. The answer needs a display representation.
2. **Difficulty-varying content.** "Add Fractions" changes its question CONTENT based on the Easy/Medium/Hard (Speed) selector. No existing generator does this — generators are speed-agnostic today; speed only affects game pace + score multiplier.

The three difficulty bands (driven by the Speed selector):
- **Easy** — add LIKE fractions (same denominator). Denominator 1-12. e.g. `2/5 + 1/5 = 3/5`.
- **Medium** — add like fractions WITH whole numbers (mixed numbers). e.g. `1 1/2 + 2 1/2 = 4`.
- **Hard** — add UNLIKE fractions (different denominators). e.g. `1/4 + 1/8 = 3/8`. The larger denominator is 2× or 3× the smaller (no more); the smaller denominator is 1-4 — so the maximum denominator is 12 (3 × 4).

## Stories

### Story 1: Fraction representation — extend the `Question` type

**Type:** Code (data-layer design — the foundational decision)

**Context:** The central design decision the rest of the sprint builds on. A fraction answer must carry BOTH a numeric value (for equality checks + scoring + distractor math) AND a display string (so `3/8` renders as `3/8`, not `0.375`).

**Output:**
- Extend `Question` (`src/math/types.ts`) with an optional display layer — recommended shape: `correctDisplay?: string` + `choiceDisplays?: string[]` alongside the existing numeric `correctAnswer` / `choices`. When present, rendering uses the display strings; when absent (every existing integer generator), rendering falls back to `String(numericValue)` exactly as today.
- The numeric `correctAnswer` for a fraction is its decimal value (e.g. `3/8` → `0.375`) — used ONLY for internal equality + distractor-distinctness checks, never displayed.
- Document the contract: a generator either supplies display strings for ALL choices or NONE (no partial).

**Acceptance:**
- `Question` carries an optional display layer; all 9 existing integer generators are unaffected (no display strings → unchanged rendering).
- Type-level: a fraction question is well-formed (numeric + display both present + same length).

### Story 2: Speed-aware generator plumbing

**Type:** Code (registry + draw-path change)

**Context:** "Add Fractions" picks its like/mixed/unlike band from the Speed setting. Today generators receive no speed — `drawNextQuestion` calls the generator with no difficulty context.

**Output:**
- Thread the round's `SpeedKey` to the generator at draw time. Minimal-surface approach: the generator signature gains an optional `speed` parameter; integer generators ignore it, `addFractions` reads it.
- `RoundController.drawNextQuestion` (and whatever it delegates to) passes the round's speed through.
- Keep the change additive — existing generators' signatures stay back-compatible (optional param).

**Acceptance:**
- A generator can read the round's speed if it wants to; existing generators are untouched in behavior.
- No change to the integer generators' output.

### Story 3: `addFractions` generator + unit tests

**Type:** Code + tests (the meatiest story)

**Context:** The generator itself — three difficulty bands, fraction arithmetic, reduction, distractors.

**Output:**
- New `src/math/generators/addFractions.ts`. Reads the round speed (Story 2) to pick the band:
  - **Easy** — two like fractions, shared denominator 1-12, sum rendered reduced.
  - **Medium** — two mixed numbers (whole + like fraction); sum may be a whole number (`1 1/2 + 2 1/2 = 4`).
  - **Hard** — two unlike fractions; smaller denominator 1-4, larger denominator = 2× or 3× the smaller (max 12); sum reduced.
- Fraction math helpers: GCD-based reduction (`3/6` → `1/2`), whole-number normalization (`2/2` → `1`, `4/2` → `2`), mixed-number formatting (`3/2` → `1 1/2`).
- Distractor generation producing plausible WRONG fractions — model common kid errors: added the denominators, forgot to reduce, numerator off by one. Distractors must be distinct from each other + the correct answer (both numerically and by display string).
- Unit tests: each band produces valid sums; answers are reduced; denominators obey the rules (Easy 1-12, Hard smaller 1-4 / larger 2-3× / max 12); distractors are distinct + plausible; mixed-number formatting is correct.

**Acceptance:**
- Generator produces correct, reduced fraction sums for all three bands.
- Denominator rules hold across many seeded runs.
- Distractors are distinct + plausible.
- New test file is green; existing tests stay green.

### Story 4: Cross-game fraction answer rendering

**Type:** Code — touches all three games' answer slots

**Context:** The display strings from Story 1 need to actually render in each game's answer slot.

**Output:**
- Alien Shoot — the falling-block answer label renders the display string.
- Asteroid Field — the rock's answer label renders the display string.
- Number Climb — the rung's answer label renders the display string.
- Each game's answer-slot rendering reads `choiceDisplays[i]` when present, falls back to `String(choices[i])` when absent. Fraction strings (`3/8`, `1 1/2`) may be wider/taller than a 1-2 digit integer — verify they fit the block / rock / rung without clipping; adjust font-fit or slot sizing if needed.
- The HUD math prompt ("`1/4 + 1/8 = ?`") renders the fraction operands too — verify the prompt string from the generator reads correctly.

**Acceptance:**
- Fraction answers render as fractions in all three games — no decimals, no clipping.
- The prompt reads correctly with fraction operands.
- Integer math types render exactly as before (fallback path).
