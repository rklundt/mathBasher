## Summary

Sprint 2.4.1 shipped to staging with two scope errors caught by the project owner during pre-promotion review:

1. **Hero wiring went to the wrong game.** The new Space Robot sprite was supposed to be the **Number Climb** hero (replacing the long-standing procedural amber-rectangle placeholder — the original raw file `hero_climber.png` was the signal, and the existing `NumberClimbHero.ts` comment literally says "Story 1 swaps the Graphics for a Phaser.Sprite once art lands"). It was incorrectly wired into Alien Shoot instead, displacing the existing Speeder1/2/3 random-per-round behavior. Alien Shoot's speeders must be restored unchanged.
2. **Asteroid Field wrong-shot cap is scoped wrong.** Sprint 2.4.1 implemented the 2-shot cap as a ROUND-wide budget (`maxWrongShotsPerRound = 2`); the intent was a PER-QUESTION cap. Today the kid loses the entire 12-question round on their 2nd wrong shot total; the corrected behavior is 2 wrong shots per WAVE = that one question scores 0, advance to next.

Both fixes preserve the audit-approved iteration-2 work (the FIRE cooldown lock visual, the cooldown click SFX, the lives row, the hero picker UI). The fixes are scope corrections on top, not rewrites.

### Story 2: Asteroid Field wrong-shot cap — change from per-round to per-question

**Type:** Code (gameplay rule scope)

**Context:** Sprint 2.4.1 story 2 introduced `config.asteroidField.maxWrongShotsPerRound = 2`. The implementation increments `roundWrongShots` across the WHOLE 12-question round; the 2nd wrong shot at any point ends the round as fail. The intent was a per-question cap: 2 wrong shots within ONE asteroid wave = that question is forfeit (scores 0, advance to next).

**Spec:**

- Rename `config.asteroidField.maxWrongShotsPerRound` → `config.asteroidField.maxWrongShotsPerQuestion`. Value stays `2`. Comment updated.
- Rename `AsteroidFieldScene.roundWrongShots` → `questionWrongShots`. Reset to `0` in `startNextQuestion()` (currently reset only in `create()`).
- `AsteroidFieldScene.getStrikesRemaining()` / `getMaxStrikes()` continue to read the config + question-scoped counter. HUD lives row now repaints to ALL GREEN at the start of every question, NOT once per round. The semantic shift is "shots remaining for THIS question."
- On 2nd wrong shot of a question:
  - Existing `handleRoundWrongShotBudgetExhausted` is RENAMED to `handleQuestionWrongShotBudgetExhausted` and SHRUNK in scope:
    - The current question scores 0 (record outcome wrong, fire `questionEnded`).
    - Surviving asteroids fade out.
    - "Out of shots!" banner displays briefly (~700ms — same as today).
    - Advance to the next question via `afterQuestion(false)` — NOT `endRound()`. The round only ends when all 12 questions are complete OR by the existing timer-out / runaway paths.
  - Telemetry event renamed `AsteroidField.roundWrongShotBudgetExhausted` → `AsteroidField.questionWrongShotBudgetExhausted`.
- Existing 1.5s FIRE cooldown lockout + cooldown SFX + visual button dim all stay unchanged. Those are per-shot behaviors; the per-question cap is the deterrent layered on top.

**Output:**

- `src/core/config.ts` — rename `maxWrongShotsPerRound` → `maxWrongShotsPerQuestion` + update doc-comment.
- `src/game/scenes/AsteroidFieldScene.ts` — rename field, reset in `startNextQuestion`, rewire the "budget exhausted" path to per-question instead of round-end.
- `src/shared/telemetry-core.ts` — no change (the new event name reuses the existing `strikesUsed` / `maxStrikes` props).
- No new tests required for this single-line scope correction, but the existing playtest checklist (sprint 2.4.1 PR description) is updated.

**Acceptance:**

- 1st wrong shot per question → timer -3s, FIRE locked 1.5s (unchanged).
- 2nd wrong shot per question → "Out of shots!" banner, current question scores 0, NEXT QUESTION starts (round continues — NOT round-end).
- HUD lives row resets to full green at every new question.
- Round still ends normally after the 12th question OR on per-question timer expiry.
- Typecheck clean; existing tests stay green.
