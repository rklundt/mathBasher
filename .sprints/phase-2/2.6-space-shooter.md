## Summary

A fourth game mode with a fresh first-person framing: the kid is **inside a spaceship cockpit**, looking out the window at alien ships drifting past, each carrying a candidate answer. Click (or tap on mobile) the alien with the correct answer.

Three rendering layers:

- **Background layer** — existing space backdrop (parallax stars + nebula via `BackgroundScene`, no change).
- **Mid layer** — alien ships drifting in straight lines (with bounce). Full-screen motion.
- **Foreground layer** — full-screen cockpit interior PNG with a **transparent window cutout** in the middle. The opaque cockpit visually frames the action; the window region reveals the aliens behind. Aliens drifting outside the window region are physically there but visually occluded by the overlay.

Input is **tap-to-shoot, gated to the window region.** Taps on the opaque cockpit areas are absorbed (the overlay is input-enabled); taps inside the window hit-test against the visible aliens.

How it differs from the existing game modes:

- **Alien Shoot:** descending lanes, fixed hero ship, separate FIRE button. Space Shooter has **free drift** (no lanes), **no hero ship inside the canvas** (the kid IS the hero, inside the cockpit), and **direct-tap input** (no FIRE button).
- **Asteroid Field:** drifting answers, aim + fire button. Space Shooter removes the aim mechanic — direct tap on the alien.
- **Number Climb:** vertical platformer with rung picks. Different genre entirely.

Shared scaffolding (RoundController, HudScene, ScoreCalculator, ADR-0011 dispatch maps) carries over without change.

## Open design questions (settle before story 1)

Captured here so we don't re-derive them at sprint start. Recommendations included; each becomes a deliberate choice in story 1's commits.

1. **Cockpit window shape.** Rectangle / trapezoid / curved arch / polygon? **Rec:** rectangle for v1 — simplest hit-test (a single rect vs polygon point-in-test). The cockpit art can VISUALLY frame a rectangle to feel curved without the geometry actually being curved.
2. **Alien sprites — reuse vs new art.** Reuse Alien Shoot's existing alien batches (5 batches × 9 frames × 2 DPR tiers — already authored + processed)? Or commission new "free-flying alien ship" art? **Rec:** reuse — keeps the sprint scope tight; distinct art is a follow-up if the look needs differentiation.
3. **Math types supported.** All current 11 (add-to-10 through subtract-fractions)? **Rec:** yes — the math layer is generator-agnostic; the cross-game rendering layer (sprint 2.4 story 5) already handles fraction displays.
4. **Timer model.** Per-question countdown (Asteroid Field pattern) / cumulative round timer (Climb pattern) / none (continuous flow)? **Rec:** per-question countdown — matches Asteroid Field's "tap the right one before the clock runs out" feel.
5. **Wrong-shot penalty.** Reuse the sprint 2.4.1 Asteroid Field timer-reduction pattern? **Rec:** YES — consistency across the two tap-based modes. Same `config.spaceShooter.wrongShotTimePenaltySec` mechanic.
6. **Round size.** 12 questions (matches Alien Shoot / Asteroid Field / Climb per sprint 2.2.1 story 10)? **Rec:** confirm yes.
7. **Spawn pattern.** All 4 answers spawn at round start and drift until shot, or continuous spawn? **Rec:** all 4 at start (mirrors Alien Shoot's wave model, free-direction).

## Stories

### Story 1: Cockpit overlay asset + window-cutout geometry

**Type:** Code + assets

**Output:**

- Cockpit interior source image (project-owner Midjourney) staged in `.sprite-source/raw/` (likely a new `cockpit/` topic folder for cleanliness).
- **Recommended source dimensions: 2560×1440** — 16:9 to match the 1280×720 design canvas aspect, 2× the design resolution. Authoring at this size keeps the cockpit detail crisp on 1080p monitors (1.5× scale) and acceptable on 4K (3× scale). Authoring at design-res-only (1280×720) softens visibly on anything bigger.
- Sprite-pipeline command:
  ```
  pnpm sprite:process --kind bg --name cockpit --format webp-lossless --no-resize .sprite-source/raw/cockpit/<source>
  ```
  Notes: `--format webp-lossless` preserves clean alpha edges on the window cutout; `--no-resize` keeps the 2560×1440 source size (the current `bg` profile caps at 1280×1280, which would scale down and soften the cockpit — for THIS asset we want the full source resolution). If the `bg` profile's bounding box becomes a recurring issue, consider adding a new `cockpit` kind with its own profile.
- Output: `public/assets/sprites/bg/cockpit.webp`.
- Window-cutout geometry: defined in config as `config.spaceShooter.windowRect = { x, y, width, height }` (design-canvas pixel coords, so the rect maps correctly through FIT scaling). Drives both the visual overlay placement AND the logical tap-hit-test bounds. Story 4 reads it.
- `CREDITS.md` entry for the cockpit art (project-owner Midjourney; per existing format).

**Acceptance:**

- `cockpit.webp` ships at lossless WebP, transparent window region visible (verify by overlaying on a colored background).
- `config.spaceShooter.windowRect` defined.
- Sprite-pipeline successfully processes the source (no `--no-resize` warning if the source is already within cap).

### Story 3: Alien drift system + window-bounded rendering

**Type:** Code

**Output:**

- `SpaceShooterAlienWaveSystem` — mirrors `AsteroidWaveSystem`'s spawn logic but simpler (no orbit math; straight-line drift with screen-edge bounce).
- Per-question wave: 4 aliens spawn simultaneously at round start (one per answer choice, per the recommendation), each with a random initial velocity (drift direction + speed). On wall-collision, bounce.
- Alien sprites: reuse via `pickRandomAlienSpriteKey()` (per the recommendation). Each alien carries an `answer: number` + `answerDisplay?: string` — same display-layer contract as Alien Shoot's wave (sprint 2.4 story 5).
- Z-order: `BackgroundScene` → SpaceShooterScene aliens → cockpit overlay. The overlay's opaque cockpit visually hides aliens that drift outside the window; the alpha cutout reveals the ones inside.
- No clipping geometry needed in code — z-order does the visual work for free. Aliens still PHYSICALLY drift across the full screen; they're just invisible outside the window.

**Acceptance:**

- A wave of 4 aliens spawns when a question starts.
- Aliens drift smoothly, bounce off screen edges.
- Aliens are visually visible only inside the window region (cockpit overlay occludes them elsewhere).
- Fraction-display aliens render correctly (regression check on sprint 2.4 story 5's display layer).

### Story 4: Tap-to-shoot input (window-bounded)

**Type:** Code

**Output:**

- The cockpit overlay is input-enabled (Phaser `setInteractive` on the overlay image). It absorbs pointer events on its opaque cockpit areas (taps outside the window do nothing).
- A separate input-enabled `Rectangle` matching `config.spaceShooter.windowRect` sits between the alien layer and the cockpit overlay. Taps on the window region check against the visible aliens — pointer-down checks each alien's screen position against the tap point + bounds-test.
- Tap on the correct alien → record correct, advance to next question (per `RoundController.recordOutcome` + the standard `correctHit` event flow).
- Tap on a wrong alien → record wrong, apply the wrong-shot penalty per story 5.
- Tap outside the window → ignored (absorbed by the cockpit overlay).
- Mobile-first verified: tap precision on a 6-10yo finger size (alien sprites are 96-128px in design coords; should be plenty large).
- Keyboard accessibility deferred for v1 (it's a tap-driven mode). Follow-up story if needed.

**Acceptance:**

- Tap on the correct alien advances the question + adds score.
- Tap on a wrong alien applies the penalty (story 5).
- Taps on the cockpit (outside window) do NOTHING — no penalty, no advance.
- Works equally on desktop click + mobile tap.

### Story 5: HUD + scoring + per-question timer + wrong-shot penalty

**Type:** Code

**Output:**

- Standard `HudScene` integration — prompt + timer + progress dots. Implements `getCountdownSec()` / `getCountdownFraction()` from `GameSceneContract` (mirroring AsteroidFieldScene).
- Per-question countdown timer per the recommendation. `config.spaceShooter.speed[speedKey].countdownSec` — values mirroring Asteroid Field (likely 25 / 18 / 12; tune in playtest).
- Wrong-shot timer-reduction penalty per the recommendation. `config.spaceShooter.wrongShotTimePenaltySec` — same pattern as the 2.4.1 Asteroid Field fix. Tune the seconds in playtest.
- Round structure: 12 questions per round (matches all other modes — `config.round.questionsPerRound`).
- Scoring: standard `ScoreCalculator` formula. **No new scoring multiplier** — Space Shooter is a GAME MODE, not a math type. The `mathDifficulty` map keys on math types, not game modes. Cross-game parity (sprint 2.2.1 story 11, sprint 2.4 story 7) guarantees the max per `(mathId, speedKey)` is the same in Space Shooter as in the other three modes. No `config.scoring.mathDifficulty.spaceShooter` entry needed; ScoreCalculator constructor takes only `(mathId, speed)` — game-axis-free by design.
- ScoreCalculator parity tests extended to confirm Space Shooter rounds match the existing per-`(mathId, speed)` max (defensive — locks the cross-game-parity invariant).
- Per-game music + midground audio entries in `GAME_MUSIC_MAP` / `GAME_MIDGROUND_MAP` — pick / process later or reuse Alien Shoot's. (Stub null entries for v1 if no Space-Shooter-specific tracks exist yet.)

**Acceptance:**

- HUD shows prompt, timer, dots correctly.
- Timer visibly drops on each wrong shot (per the penalty config).
- 3-4 rapid wrong shots cause the question to time out — same self-balancing behavior as the 2.4.1 Asteroid fix.
- Round ends after 12 questions; score + stars derived from the standard ladder.
- ScoreCalculator parity test passes (Space Shooter perfect round = other modes' perfect round at the same `(mathId, speed)`).
