## Summary

mathBasher is deploying to **Azure Static Web Apps** (decided 2026-05-22). The game is a 100 % static Vite SPA — no backend needed for gameplay — so SWA is the cheapest + simplest fit. The Express server (`/server/`) stays in the repo unbuilt-for-deploy so a future "mature to App Service" move is a deployment-target swap, not a rewrite.

This sprint absorbs the **Phaser-chunk CDN cache-header story** — formerly sprint 2.2.1 Story 13, which was BLOCKED there because cache headers needed a deployment target to exist. On Static Web Apps the cache policy is just a committed `staticwebapp.config.json` file, so the work is **no longer blocked** — it lands here alongside the deploy.

(This supersedes the App-Service-based plan in the older sprint 3.5; 3.5 should be re-scoped or retired now that the hosting decision is SWA. Out of scope for this sprint — flagged for the 2.3 wrap-up.)

## Stories

### Story 1: `staticwebapp.config.json` — cache headers + SPA routing

**Type:** Code (config)

**Context:** The Phaser vendor-chunk split shipped in sprint 2.2 (`vite.config.ts` `manualChunks` → `phaser-<hash>.js` + `index-<hash>.js`). The caching payoff only lands if the host serves hashed assets with long-lived immutable cache headers. On Azure Static Web Apps that's a committed `staticwebapp.config.json` — no infrastructure, no blocker (this is what un-blocks the former 2.2.1 Story 13).

**Output:**
- New `staticwebapp.config.json` at the repo root:
  - Hashed build assets (`/assets/*`) → `Cache-Control: public, max-age=31536000, immutable`.
  - `index.html` → `Cache-Control: no-cache` (un-hashed entry point — must re-fetch to pick up new asset hashes).
  - `navigationFallback` → `index.html` so any deep-link / refresh serves the SPA entry point (mathBasher is a single-page Phaser app).
  - MIME-type correctness for `.webp` if SWA doesn't serve it right by default (verify).
- Verify against the SWA build output structure (Vite's `dist/assets/`).

**Acceptance:**
- Hashed assets served `immutable`; `index.html` served `no-cache`.
- A returning visit reuses the cached `phaser-*.js` (DevTools Network → "(disk cache)").
- Deep-link / refresh on any path serves the app, not a 404.

**Type:** Code + docs

**Context:** The Azure Static Web App is linked to the GitHub repo by hand (the wizard generates a `.github/workflows/azure-static-web-apps-*.yml`). This story makes the generated pipeline correct + documented.

**Output:**
- Confirm the generated GitHub Action builds correctly: app location `/`, output location `dist`, `pnpm` auto-detected from `pnpm-lock.yaml`.
- If the build command needs pinning, set it (the project's `build` script also runs the server `tsc` — harmless for the static deploy, but a `build:web`-only script could be added to skip it if the pipeline wants leaner).
- Confirm `?autostart` + URL params still work on the deployed site.
- Document the deploy flow in `DeveloperGuide.md` — how a push to `main` ships to the SWA, where the URL is, how to roll back.

**Acceptance:**
- A push to `main` builds + deploys to the SWA URL automatically.
- The deployed site loads + all three game modes play.
- DeveloperGuide documents the deploy + rollback flow.
