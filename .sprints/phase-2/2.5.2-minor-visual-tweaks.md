## Tweak list (project owner, 2026-06-26)

### Story 1: Hero Chooser — subtitle overlaps the top card row

**Type:** Code (layout)

The "Just for looks — pick the one that feels like you." subtitle (`HeroChooserScene`, at `height*0.17`) visually overlaps the top of the 2x2 card grid. Move the subtitle up and/or push the grid down (and/or tighten card height) so the subtitle clears the cards on the design canvas at the common viewport aspect ratios.

**Acceptance:** subtitle is fully clear of the top card row; title/subtitle/grid read as three separate bands.

### Story 2: Space Escape (DifficultyScene) — floor-count subtitle covered by buttons

**Type:** Code (layout)

On Number Climb's difficulty screen, the "12 floors..." subtitle is partially covered by the difficulty buttons. (Related to the sprint 2.4 Story 0 carry-in overflow fix, but the floor-count line specifically still collides.) Reposition so the subtitle sits clear above the button stack.

**Acceptance:** the floor-count subtitle is fully visible, not overlapped by any button, on mobile + desktop.

### Story 3: Space Escape hero — 33% larger + bottom-aligned per floor

**Type:** Code (entity sizing + positioning)

The Climb hero (the Space Robot climber) is (a) too small and (b) vertically centered in its floor band. Make it **33% larger** and reposition so it sits **a few pixels above the bottom of each floor/level** rather than centered. Touches `config.numberClimb.hero` dimensions (or the sprite scale in `NumberClimbHero`) + the hero's y-placement math in `NumberClimbScene` (floor0Y / per-floor y). "A few pixels from the bottom" — pick a small lifted gap (target ~6-10 px above the floor band's bottom edge; tune in playtest).

**Acceptance:** hero renders ~33% larger; its feet sit just above the floor bottom on every floor (start floor + each climbed floor + the escape floor), not centered.

### Story 4: Alien Shoot mobile — browser URL bar covers the speeder

**Type:** Code (mobile viewport / safe area)

**Context:** In phone portrait, the mobile browser's URL bar overlays the top or bottom of the canvas. When it's on the bottom, it covers the speeder (the Alien Shoot hero sits near the bottom), so the player can't see it. Needs a viewport/safe-area fix so the playfield's interactive bottom edge (where the hero runs) stays clear of the browser chrome.

**Investigation first:** check the current viewport handling (`100vh` vs `100dvh` / `visualViewport`, `env(safe-area-inset-*)`, and where the Alien Shoot hero's y is anchored). Likely fix is some combination of dynamic-viewport units + lifting the hero's run-line up by a safe-area margin. **May warrant a design decision** on approach — flag before committing if non-trivial.

**Acceptance:** on a phone in portrait, the Alien Shoot speeder is fully visible regardless of whether the browser URL bar is shown top or bottom.

### Story 5: Alien Shoot — slow alien drop 15% on slow + medium tiers

**Type:** Code (config tuning)

The speeder doesn't make enough back-and-forth passes before the aliens reach it on the easier tiers. Reduce alien descent speed by **15%** on the **slow** and **medium** speed tiers (leave **fast** unchanged). Reduce both `descentPxPerSec` AND `penaltyPxPerSec` (the wrong-shot accelerated drop) by 15% so they stay proportional.

- slow: descent 41 -> 35, penalty 123 -> 105
- medium: descent 62 -> 53, penalty 185 -> 157
- fast: unchanged (93 / 278)

`config.alienShoot` (or `config.scoring.speed` block) edit only.

**Acceptance:** slow + medium alien descent is ~15% slower; fast unchanged; scoring unaffected (descent speed is game-mechanic tuning, not a score multiplier).

### Story 6: Space Escape — remove per-floor 2-wrong cap (3 lives total only)

**Type:** Code (gameplay rule) — added mid-sprint by project owner.

**Context:** Climb had TWO overlapping wrong-pick rules from sprint 2.4.1: a per-floor "2nd wrong on a floor ends the round" terminal AND a cumulative 3-life cap. The 3-dot lives HUD shows the cumulative cap, so a kid could "die" from two wrongs on a single floor while the HUD still showed a life remaining — confusing. Remove the per-floor terminal; the cumulative **3 lives total** becomes the sole wrong-pick round-ender, matching the HUD exactly.

**Spec:**
- `numberClimbFloorMath.ts` — `resolveRungPick` returns `wrong-mulligan` for EVERY wrong pick (no `wrong-terminal`); the `RungPickKind` / `RungPickOutcome` types drop the `wrong-terminal` variant.
- `NumberClimbScene` — remove `handleWrongTerminal` + its dispatch case; every wrong flows through `handleWrongMulligan`, which spends a life and ends the round only when the cumulative cap is hit.
- First-wrong banner copy "One more try!" → "Lost a life — keep going!" (the old copy implied a single per-floor retry).
- Update all stale docs/comments (scene, FloorSystem, config, sceneKeys) that described the per-floor terminal.
- Tests — `NumberClimbFloorSystem.test.ts` terminal-outcome cases updated to assert always-mulligan.

**Acceptance:** a wrong pick always lets the kid retry (as long as lives remain); the round ends precisely when the 3rd life is spent (HUD shows 0), never with a life still showing; a kid can spend all 3 lives on one hard (4-rung) floor or one each across three floors.

### Story 7: Local pnpm/Corepack setup docs (close a 2.5.1 gap)

**Type:** Docs — added mid-sprint by project owner.

**Context:** The sprint 2.5.1 toolchain upgrade (pnpm 9.15 → 11.9.0, Node 20 → 22) bumped CI + `engines` + Dockerfile but did NOT update the human-facing setup docs, which still said Node 20 / pnpm 9.15.0 AND recommended `npm install -g pnpm` — the exact global install that shadows Corepack and pins you to an old pnpm. That shadowing bit the project owner: `pnpm dev` ran the global 9.15.0, which can't parse the new `pnpm-workspace.yaml` (`ERROR packages field missing or empty`). The actual fix is per-machine (`corepack enable`, remove the global), so the repo deliverable is correct + warned documentation.

**Spec:**
- README.md + DeveloperGuide.md prerequisites → Node 22.13+ / pnpm 11.9.0; Corepack as the ONLY supported path; explicit warning against `npm install -g pnpm`; troubleshooting block (`npm uninstall -g pnpm` if `pnpm --version` ≠ 11.9.0).
- Sweep both docs for remaining stale `Node 20` / `pnpm 9` / `node:20-alpine` references (architecture table, server notes).
- `dev.bat` (gitignored local launcher) already invokes `corepack pnpm dev` to sidestep the shadowing — no repo change, noted here for completeness.

**Acceptance:** README + DeveloperGuide describe the correct toolchain (Node 22 / pnpm 11 / Corepack-only) with the shadowing-global warning + fix; no stale 20/9.15 references remain in those docs.
