## Stories

### Story 1: Mulligan UX hint — "One more try!" + −3s timer popup

**Type:** Code + polish (Support review must-fix #1)

**Context:** Sprint 2.2 audit finding — when a kid picks a wrong rung in Number Climb, the rung dims and the hero falls back, but they get NO visual cue that they have only ONE retry. A first-time player can think the wrong rung is just disabled and freely guess again, then be surprised when the second wrong ends the round.

**Output:**
- On the first mulligan of a kid's first session (sessionStorage flag), show a brief "One more try!" banner above the hero for ~1.5 s.
- On every mulligan, render a floating "−3s" popup at the timer (mirror the existing `correctHit` score-popup pattern from Alien Shoot) so the kid registers that time was the cost.

**Acceptance:**
- First mulligan ever in a session: "One more try!" banner appears, fades after 1.5 s.
- Every mulligan: "−3s" red text floats up from the timer for ~800 ms.

  - `SIDE_BAR_WIDTH` (20)
  - `SEPARATOR_THICKNESS` (12)

**Acceptance:**

### Story 6: WebP migration for backgrounds + sprite art

**Type:** Code + assets (DevOps review nice-to-have #2)

**Context:** Number Climb's 19 floor PNGs total ~5.5 MB. Sprite pipeline currently outputs PNG only. WebP is universally browser-supported (Safari since 14, Phaser handles it natively — alien spritesheets are already WebP). Migration saves ~4 MB on the Climb game-bundle download + ~1 MB on boot for backdrops.

**Scope (decided during sprint planning):**

| Asset family | Files | Mode | Expected savings |
|---|---|---|---|
| Floor backgrounds | 19 (climb-floor-fire, escape, room-1..16) | **lossy q85** | ~60 % → ~3.3 MB |
| Game backdrops | 2 (nebula, asteroid-belt) | **lossy q85** | ~60 % → ~850 KB |
| Title splash | 2 (Title-Splash-1, -2) | **lossy q85** | ~60 % → similar |
| Hero ships | 7 (speeders + asteroid-heroes + escape-ship) | **lossless** | ~25 % → ~30 KB |
| Asteroids | 8 (asteroid-1..8) | **lossless** | ~25 % → ~30 KB |
| UI sprites | n/a | skipped | already tiny |
| Particle sprites | n/a | skipped | already tiny |

Lossy q85 for no-alpha backgrounds (no edge-halo concern, 60% savings). Lossless for alpha sprites (clean transparent edges, smaller absolute savings but consistent quality).

**Output:**
- Extend `scripts/sprites/process.mjs` to support `--format webp` (lossy q85) and `--format webp-lossless` flags. Sharp already supports WebP output natively (`sharp(...).webp({ quality: 85 })` or `.webp({ lossless: true })`); the change is parsing the new flag + dispatching the encoder.
- Re-process all 36 in-scope assets through the new pipeline. Move existing `.png` files to `.sprite-source/raw/processed/` or delete (per audio-pipeline convention).
- Update `spritePath()` / `SPRITE_MANIFEST` to use `.webp` extensions for the migrated assets. Two paths to consider:
  - **Option A**: change `spritePath` to return `.webp` for the migrated kinds; force-route in one place.
  - **Option B**: per-entry `extension` field on SpriteManifestEntry. More flexible, more LOC.
- Verify Phaser loader handles `.webp` for non-spritesheet single images (it does — used by alien spritesheets — but a manual smoke-test confirms).
- Manual playtest all three game modes to confirm visual quality (especially the floor backgrounds at lossy q85).

**Acceptance:**
- Number Climb game-bundle download drops by ~3 MB.
- Boot bundle drops by ~1 MB (nebula + asteroid-belt).
- Hero + asteroid sprites visually identical (lossless), backgrounds visually indistinguishable from PNG at normal viewing (lossy q85).
- All 337 tests still pass.
- `pnpm build` succeeds; build output reflects the smaller asset payload.

### Story 7: Code + type cleanup (audit small-fixes)

**Type:** Refactor (Senior Dev + Architect review small-fixes)

**Context:** A cluster of tiny code-quality items from the 2.2 audit, batched into one story so they don't fragment into one-line commits.

**Output:**
1. **Dead code** (Senior Dev #1-2): delete `void config;` + the `import { config }` it preserves in `NumberClimbFloorSystem.ts` (also check `numberClimbFloorMath.ts` — the architect flagged a `void config;` there too; remove whichever sites are genuinely unused). Delete `void topPlayfield;` + the unused local in `NumberClimbScene.ts`.
2. **HudScene cast** (Architect #7): `HudScene.ts` casts `this.scene.get(this.gameSceneKey) as Partial<GameSceneContract> | null`. Phaser's `scene.get()` never returns null — drop the `| null` from the cast (or replace the cast with a typed helper). The spurious `| null` masks the real contract.
3. **Cooldown auto-restore telemetry** (Senior Dev #9): `NumberClimbInputSystem`'s `POST_PICK_COOLDOWN_MS * 4` auto-restore is a defensive safety net for a stuck input-accepting state. If it ever actually fires, that means the scene forgot to call `acceptInput()` — a real bug. Add a `Warning`-severity `_th.logToAi` event inside the auto-restore branch so the safety net surfaces in telemetry instead of silently masking a scene bug.
4. **Type tighten** (Architect nice-to-have): `NumberClimbFloorSystem.usedFloorBgKeys` is typed `string[]` but only ever holds `ClimbFloorBgKey` values (the return type of `pickRandomClimbFloorBgKey`). Tighten to `ClimbFloorBgKey[]` so a typo'd push is a compile error.

**Acceptance:**
- Both dead-code anti-pattern sites removed.
- HudScene cast no longer carries the spurious `| null`.
- The input-cooldown auto-restore emits a Warning telemetry event if it fires.
- `usedFloorBgKeys` typed `ClimbFloorBgKey[]`.
- Typecheck + tests stay green.

### Story 8: Test gap — FloorSystem.pickRung state-machine coverage

**Type:** Tests (Senior Dev review should-fix #6)

**Context:** `NumberClimbFloorSystem.pickRung` returns one of 4 outcome kinds (`'correct'` / `'wrong-mulligan'` / `'wrong-terminal'` / `'rung-consumed'`). The pure subset math (`pickSubsetWithCorrect`) is covered; the state-machine that owns `wrongsThisFloor` and decides terminal vs mulligan is NOT.

**Output:**
- Add a thin test file `src/game/systems/NumberClimbFloorSystem.pickRung.test.ts` (or extend the existing `NumberClimbFloorSystem.test.ts`) with mock scene + mock rung that walks each outcome:
  - First correct pick → `kind: 'correct'`
  - First wrong pick → `kind: 'wrong-mulligan'`
  - Second wrong pick on same floor → `kind: 'wrong-terminal'`
  - Re-pick a consumed rung → `kind: 'rung-consumed'`
  - Pause state guards correctly
- Mock the rung's `answer` + `consume()` + Phaser container methods minimally (existing test files like `LoadingOverlay.test.ts` have a mock pattern to copy).

**Acceptance:**
- All 4 outcome kinds covered by tests.
- Existing 337 tests still pass; new tests add to that total.
