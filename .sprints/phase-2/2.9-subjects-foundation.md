# Sprint 2.9: Subjects foundation — challenge-first flow

**Phase:** 2
**Status:** Planned — design agreed with the owner (wireframes, 2026-10-20) and reviewed; two open questions for the owner
**Closed:** —
**Released:** —
**Blocks:** The next game modes (Pair Pals, Number Line Hop, …) and any non-math subject.
**Depends on:** 2.8 (Released).
**Estimated effort:** 3–4 days across three releasable steps, plus the owner's naming decision.

## Summary

An architecture sprint: no new games. It gets the app ready to grow beyond math as **one umbrella app** (the owner's direction, 2026-10-19), which is also what a future Android / iOS wrap would need.

The flow becomes **Subject → Challenge type → Game → Difficulty**. "Challenge type" is today's math type (Add to 10, Subtract Fractions…): "topic" was too bland for kids.

It ships in three steps, each releasable on its own:

1. **Challenge-first flow (2.9.0).** The challenge is picked first, from a subject (only Math for now), and stays put while you hop between games. Difficulty is still picked per game, with its own labels. Every screen gets a kid-friendly heading, and the points are shown in kid terms ("1.5x Points!", "Up to 1,500 points!"). Players see the change.
2. **Subject → challenge model (2.9.1).** In code, "math type" becomes a challenge inside a subject. Players see no change; the code is ready for a second subject.
3. **Name and store-app assessment (decisions, no code).** The umbrella name (the owner's call) and a written assessment of wrapping the app for the app stores.

## Decisions (owner, 2026-10-19 / 20)

- **One umbrella app**, Subject → Challenge type → Game. No cloned repos and no family of sites.
- **Naming for kids:** "challenge" in the UI (the chip says "Challenge: Add to 10 ✎"). Every screen has a heading.
- **Subject:** a "Math" subject tab is there from the start and selected, and its challenges show straight away. There's no "coming soon" tab: subjects appear when they exist.
- **The challenge picker opens on the first Start of every visit.** A reload resets the challenge and difficulty (accounts may save settings later, not now).
- **The challenge is easy to swap** from Game Select and from Difficulty (the chip), and from Pause and Game Over ("Change challenge").
- **Difficulty stays per game**, picked after the game, so it keeps the per-game labels ("3 holes · 25s").
- **Points, in kid terms:** under every challenge button its multiplier ("1x Points", "1.5x Points!" … "4.5x Points!"; no "!" on 1x). On Difficulty, each level shows the round's top score for the challenge ("Up to 1,500 points!").
- **A new umbrella name** is needed before a second subject ships: "mathBasher" won't fit words.
- The next-game ideas (Pair Pals, Number Line Hop, Balance Scale, Kitty Café, Pattern Train, two-player duel) are parked until this sprint lands.

## Design review (Story 1)

Kid UX, architecture and senior dev reviewed the agreed design against the code (2026-10-20). Nobody asked to change the structure or naming. Their findings, folded into D1 below:

- **No model work first.** Step 1 ships before step 2. The picker's order already matches `config.scoring.mathDifficulty`; labels come from the generators and multipliers from config. New code uses "challenge" names, but `Settings.setMathId` stays until step 2 renames it once.
- **First visit = "no challenge yet".** The picker opens whenever `Settings.round.mathId` is null. That is in-memory state, so a reload resets it and Main Menu keeps it; no new flag. Difficulty stops quietly filling in the first challenge, and if it's ever reached without one it sends the kid to the picker. The unused `Settings.reset()` goes, so nothing re-triggers the picker by accident.
- **The picker is its own scene** (`ChallengePickerScene`), started with `scene.start`, never laid over another scene (Esc handlers would stack). Each opening says where a pick goes (`next`) and where Back / Esc goes (`back`), set fresh every time:

  | Opened from | Pick → | Back / Esc → |
  | --- | --- | --- |
  | First Start | Game Select | Menu (no challenge set; the picker opens again next Start) |
  | Game Select chip | Game Select | Game Select |
  | Difficulty chip | Difficulty | Difficulty |
  | Game Over | Difficulty (this game) | Game Over |
  | Pause | see the open question below | |

- **"Up to" scores** come from one pure, tested function, `maxRoundScore(mathId, speed, questions)`, next to `ScoreCalculator`, with each game's own question count (Space Escape's differs) from a shared `questionsPerRoundFor(gameId)`. A test checks it equals a perfect `ScoreCalculator` round. Values are rounded and formatted the same everywhere ("1,500"); the top is 8,100.
- **Bigger targets.** Today's 56-tall buttons are about 28 CSS px on a phone, under the 44 px minimum. The picker uses 280 × 96 buttons in a 4 + 4 + 3 grid, with the label and "1.5x Points!" inside; Difficulty tiles 240 × 96 with the game label inside and the "Up to" line under each.
- **Pause and Game Over re-layout.** A fifth pause button runs into "Paused", and the Game Over 2 × 2 grid runs past the bottom gutter. Both use Resume / Play again on top and a 2 × 2 grid under it, from a new tested `computeGridSlots` helper; the "New High Score" badge moves clear of Play again.
- **The chip:** a 360 × 72 pill with a challenge glyph ("+", "÷", "½") and a swap icon. ✎ reads as "write" to a kid, and the game font may not have it. Keyboard focus lands on Start / the first tile, not on the chip (an Enter-masher would land in the picker every time); the chip stays first in Tab order. The current challenge is ringed and ticked in the picker, and focus starts on it.
- **Fraction challenges:** their Difficulty tiles add a second line (like fractions / mixed numbers / unlike), because Hard changes the content, not just the speed.
- **Telemetry:** keep `mathId` as the property name. `ChallengeChanged` fires only on a real change, with where it came from. Leaving a round adds `sceneKey` to `RoundAbandoned`.
- **Keep step 2 small:** the `SubjectId` / `ChallengeId` types in `core`, and a registry that only lists the challenges per subject (labels stay in the generators, multipliers in config). The per-game answer kinds and the word-label check wait until a second subject needs them.
- **Fun, within the design:** the chip bounces when the challenge changes; it wiggles once the first time Game Select opens in a visit; the points line can be a sticker whose colour warms from 1x to 4.5x.

**Open questions for the owner:**
1. **High Scores doesn't exist yet.** The Menu button only says "No scores yet", and scores are kept for the visit only. Showing the challenge next to each score means building the High Scores screen. Build it in 2.9.0, or leave it for later (it fits better with accounts)?
2. **Change challenge from Pause.** Kid UX wants Back to return to the paused round (the round only ends if a different challenge is picked). Architecture and senior dev want the picker as its own scene, which means the round ends the moment you open it. Recommended middle ground: Pause shows the challenge buttons inside its own card; Back returns to the pause buttons with the round intact; picking a different challenge ends the round (not scored) and goes to this game's Difficulty.

## Design

### D1. Screens and flow (step 1)

Wireframes agreed with the owner (2026-10-20):

| # | Screen | Heading | What's on it | Goes to |
| --- | --- | --- | --- | --- |
| 1 | Menu | (title) | Start, High Scores, Settings | Start → 2 on the first Start of the visit, otherwise → 3 |
| 2 | Challenge picker | "Pick your challenge!" | Subject tab "Math" (selected); 11 challenge buttons, whole numbers then Mixed and fractions; under each, "1.5x Points!" | a challenge → back where it was opened from (3 on first visit) |
| 3 | Game Select | "Pick a game!" | chip "Challenge: Add to 10 ✎"; 8 game tiles (4 + 4); Back | a game → 4; chip → 2 → 3 |
| 4 | Difficulty (per game) | "Bunny Garden: how tough?" | chip; Easy / Medium / Hard with the game's labels and "Up to 1,500 points!"; Back, Start | Start → Loading → game; chip → 2 → 4; Back → 3 |
| P | Pause | "Paused" | Resume, Settings, Change challenge, Change game, Quit to menu | Change challenge → 2 → this game's 4; Change game → 3 |
| 6 | Game Over | "Round complete!" | score, stars; Play again; a 2 × 2 grid: Change difficulty, Change challenge, Change game, Main menu | Play again → game; Change challenge → 2 → 4; others as today |

- **"Up to" scores** come from the scoring config: `12 × basePerCorrect × challenge multiplier × difficulty multiplier`, so they never drift from the real scoring. They assume a clean round (a right answer after a miss is worth half).
- **Leaving a round** by Change challenge (Pause) isn't scored, like Change game today.
- **Fraction challenges** change content with difficulty (like fractions, mixed numbers, unlike fractions); the Difficulty tiles may say so (review question).
- **High Scores:** the challenge belongs next to each score (a 7,200 in fractions isn't comparable to a 1,200 in Add to 10), but the screen doesn't exist yet (open question 1).
- **Keyboard:** the chip is the first stop on 3 and 4; Esc closes 2 (back to where it was opened). Enter / Space pick.
- **Telemetry:** `ChallengeChanged` (with `mathId`), and the screen events follow the new order.

### D2. Subject → challenge model (step 2)

- **Names:** `SubjectId` (today only `'math'`), `ChallengeId` (today the existing `MathId` values). A small registry maps subject → challenges → question generator and display metadata (label, section, multiplier).
- **Question layer:** the `Question` shape (prompt, choices, right answer, displays) already fits other subjects. The generator registry moves from math-only to subject-aware; the math generators don't change.
- **Game support:** each game lists the answer kinds it can show (whole numbers, fractions, later words). Game Select greys out a game that can't play the current challenge (none today).
- **Answer labels:** `MathText` keeps the mixed-number rule; a word answer needs its own fit check in every game's carrier. This sprint adds the check, not the words.
- **Kept stable:** the `mathId` telemetry property, the scoring and time tables (keyed by challenge), and the persisted settings keys.

### D3. Name and store-app assessment (step 3, decisions only)

- **Name:** where "mathBasher" appears today (title, splash, page title, footer, web manifest, README, repo, domains), what changes for a rename and in what order. The owner picks the name.
- **Store app:** wrapping options (for example Capacitor), offline assets, the kids-store rules (Google Families, Apple Kids Category) and COPPA; what that pulls forward from Phase 4 (privacy policy, analytics review, a parent gate). Recorded as an ADR.
