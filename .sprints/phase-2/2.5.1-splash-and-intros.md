## Carried-in design context (from sprint 2.5 conversation)

The following architectural decisions were locked during the 2.5 design discussion and stay valid for 2.5.1:

- **Format approach:** static WebP today, designed for animated-WebP swap later. `<img>` tag in DOM; no JS swap logic needed.
- **Wordmark:** must be a CSS / DOM overlay, NOT baked into the splash image. So the static→animated swap doesn't require re-creating the wordmark in the animation.
- **Fixed aspect-ratio container:** the `#splash` div carries `aspect-ratio: 1 / 1` (square, matches both Title-Splash images); the bg `<img>` fills it.
- **File location:** `public/assets/splash/` (a new folder; signals "this might animate later"). NOT `public/assets/images/` where the current raw PNGs sit.
- **Cache strategy on swap:** tolerate the 7-day SWA cache on static→animated swap (first-time visitors get the new version immediately; returning visitors get it day 8). Don't bump filenames.
- **Interactive splash deferred:** if we ever want the kid to tap the hero and see them wave, that requires Phaser, not WebP. WebP covers static and animated; that's 95% of what a splash needs.
- **Start affordance:** Big "Tap to Play" button (keeps the existing user-gesture path for AudioContext on iOS).
