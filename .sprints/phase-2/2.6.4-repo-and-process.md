## Design

### D6. Contribution files

**CLA: deferred to counsel.** Nothing CLA-related ships this sprint except the questions below, written up for the owner and counsel.

**Owner's leaning (2026-10-16), to confirm with counsel:** (1) **assignment** of copyright; (2) **18+ only**, said plainly as a contract-law limit (CONTRIBUTING says so); (3) the **hosted CLA Assistant**, provided signatures stay traceable: the project keeps its own copy (an export, or a job that copies each signature into a private repo; to be checked when set up). Code contributions stay closed until then.

- **Mechanism.** The draft's GitHub Action (`contributor-assistant/github-action`, "CLA Assistant Lite") is **archived and unmaintained**. It would run on every fork PR with a token that can write to the repo, so it's out.
  - (a) The hosted CLA Assistant app (maintained). No write token sits in our workflows, but signatures are stored by a third party.
  - (b) A fork of the action, reviewed and maintained by the owner.
  - Whichever is chosen: signatures never go on `main` or `development`. Committing to `main` is blocked by branch protection, and a push to either branch would trigger a deploy. The safe options are a private repo or a dedicated `cla-signatures` branch with deletion and force-push blocked.
  - If any `pull_request_target` / `issue_comment` workflow lands, it must follow these limits:
    - Never check out the PR's code.
    - No `${{ github.event.* }}` inside `run:`.
    - Minimal job-level permissions.
    - No `environment:`, no repo secrets.
    - The `production` environment requires the owner's approval for each deploy.
- **Copyright model** (must be decided first):
  - (a) Assignment with a licence back to the contributor.
  - (b) An exclusive licence.
  - (c) A non-exclusive licence. Then the "only Ray Klundt in copyright lines" header rule changes, and enforcing the AGPL on contributed code gets harder.
- **Minors.** A kids' game will attract minors, and a minor can usually cancel a contract. Options: an "I am of legal age" statement plus a parent or guardian co-signature route, or decline code from anyone who can't make that statement.
- **What the CLA must cover:**
  - a perpetual, irrevocable, royalty-free grant with the right to relicense, including commercially
  - a patent grant (Apache-style, ending if the contributor sues)
  - the contributor's statements: original work, no employer claim, third-party material disclosed
  - moral-rights consent, and no warranty
  - a corporate version
  - distribution under AGPL-3.0-or-later *including the NOTICE §7(b) attribution term*
  - a versioned document
- **Privacy.** Signature records (GitHub handle, ID, PR number, time) in a public repo become a permanent list. Prefer private storage.
- **CLA, not DCO.** A DCO sign-off gives only AGPL rights in, not the relicensing right the commercial licence needs. A DCO `Signed-off-by` line may be kept as well, as a provenance record.

**Templates and pages that ship this sprint:**
- **`.github/ISSUE_TEMPLATE/bug.yml`:**
  - A privacy note at the top: don't include a child's name, age, school, photos or anything that identifies them; crop screenshots to the game; never paste passwords or tokens.
  - Dropdowns: game (the six names as shown in the menu), math type, difficulty, device type (phone / tablet / Chromebook / computer), browser.
  - Text fields: "What happened" and "What did you expect".

  - No required version or commit, since players can't see one.
- **`idea.yml`:** the same privacy note, and "Ideas from kids are welcome — tell us in their words."
- **`config.yml`:** blank issues off. Contact links:
  - "Security problem? Report it privately" → the repo's private advisory form (`/security/advisories/new`).
  - `SECURITY.md`.
- **`.github/PULL_REQUEST_TEMPLATE.md`:** summary, how it was tested, and a checklist:
  - tests pass
  - SPDX header on new files
  - no secrets
  - changes to `.github/`, `.githooks/`, `package.json` scripts, the lockfile, `pnpm-workspace.yaml` or the lint config called out for extra review
  - CLA: "required once contributions open"
- **`CONTRIBUTING.md`:**
  - "Reporting bugs" moves to the top, in plain words.

  - The CLA section points to the open decision.

### D7. Local checks

**New dev dependencies:**
- `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-config-prettier` (**≥ 10.1.8**: 10.1.6 and 10.1.7 shipped malware that targeted Windows), `prettier`.
- All MIT, dev-only, with no install scripts. None is added to `allowBuilds`.
- pnpm's `minimumReleaseAge` is one day, so a version that was just compromised can't be installed straight away. (Planned as a few days; pnpm also checks the lockfile against it, so a longer wait would block CI after every update.)
- The lockfile diff must resolve only to `registry.npmjs.org`. `pnpm audit` must be clean.
- Recorded in **ADR-0013**, following the one-ADR-per-dev-tool precedent (ADR-0008 and ADR-0009).

**ESLint** (flat config):
- `typescript-eslint` recommended + type-aware rules in CI, e.g. no floating promises.
- Files outside the other tsconfigs (`server/**/*.test.ts`, `vitest.config.ts`, `eslint.config.js`) are covered by the type service's default project (`allowDefaultProject`), which needed no extra `tsconfig.eslint.json`. `scripts/**/*.mjs` is linted without type info.
- `no-restricted-imports` per folder enforces ADR-0006: Phaser only in `src/game/**` and `src/app/boot.ts`; `math/` and `services/` stay Phaser-free; `math/` is also DOM-free (`services/` may read `localStorage`, per ADR-0006).
- `no-restricted-syntax` bans `innerHTML` / `outerHTML`.
- Existing hits are fixed or justified line by line.
- `pnpm lint`, with `--cache` locally.

**Prettier:**
- `printWidth: 120` (matches `.editorconfig`), `singleQuote`. The rest of the current style already matches Prettier's defaults.
- Scope: `ts`, `mjs`, `json`, `yml`. Not `.md`; docs and sprint prose are left alone.
- A `.prettierignore` excludes the lockfile, `public/assets/**`, `.pnpm-store`, `coverage`, `dist`, `.sprints` and the legal texts.
- Deploy configuration (`.github/workflows/*`, `public/staticwebapp.config.json`, `infra/**`) is either excluded or its diff reviewed by hand.
- Expected churn: a few hundred lines.
- Scripts: `pnpm format` / `pnpm format:check`.

**The reformat lands safely** (this repo squash-merges, which would swallow a "format-only" commit). Order of operations:
1. **Release v2.6.3 / 2.6.4 as usual**, but hold its "released" record (the sprint-file and plan update) for step 4. Otherwise that commit would ride along in the next release.
2. **The reformat PR.** One commit made from the development tip with `pnpm format` and nothing else; running `pnpm format` on its parent must reproduce it exactly. Merged with **"Create a merge commit"** (`gh pr merge --merge`), not squash or rebase, so the reformat commit keeps its ID on development.
3. **A reformat-only release to main.** It uses the usual release path (branch from `origin/main`, `git read-tree -u --reset origin/development`, admin squash-merge). First confirm `origin/main` and the merge's first parent have no differences, so main's squash commit is exactly the reformat. No version bump and no changelog entry, because those would hide inside the reformat. It gets a tag only (`format-2026-10`, deliberately not a version number).
4. **One follow-up PR to development:**
   - `.git-blame-ignore-revs` listing the **reformat commit** on development (the merge's second parent; blame credits lines to it, not to the merge) and **main's squash commit**
   - `pnpm format:check` in the CI job and the Prettier check in the pre-commit hook
   - the held release records
   - a DeveloperGuide note on using it: GitHub's blame view reads the file automatically; locally, `git blame --ignore-revs-file .git-blame-ignore-revs <file>`. The setup script does **not** set `blame.ignoreRevsFile`, because git then refuses to blame on any checkout without the file (older tags, or `main` before the follow-up ships).

   It reaches main with the next normal release.

**Commit hooks** (no new dependency):
- **Setup.** A `prepare` script runs `node scripts/install-hooks.mjs`, which sets `core.hooksPath .githooks` at **local** scope only. It does nothing when there's no `.git` folder, no `git` on the PATH, or `CI` is set.
  - A bare `git config` in `prepare` would break the Docker build (Alpine has no git, and `.git` is excluded) and installs from a downloaded ZIP.
  - `|| true` doesn't help either: pnpm runs scripts through cmd.exe on Windows.
- **`.githooks/pre-commit`** (sh, marked executable in the index; exFAT doesn't record that):
  - ESLint *without* type info on staged files (`--diff-filter=ACMR`, `-z`, `--`). The Prettier check joins it in the follow-up after the reformat (step 4 above).
  - Then every `*.sh` in the gitignored `.githooks/local/`, run with `sh`.
  - Typecheck and type-aware lint stay in CI to keep commits fast.
- **`.githooks/commit-msg`:** hands off to `.githooks/local/` the same way, since a commit message is permanent once committed.
- **Safety of `.githooks/local/`:**
  - The hook refuses to run if `git ls-files .githooks/local` lists anything, so a branch can't plant a script there.
  - CI fails on tracked files in that folder.
  - If the folder is missing, the hook prints a one-line notice. The owner can make that an error with `git config mathbasher.requireLocalChecks true`.
  - The folder's `.gitignore` entry and comments stay generic ("optional machine-local checks").
- `.gitattributes` marks `.githooks/**` as LF.

**`.nvmrc`:** `22`. Both workflows switch to `node-version-file: .nvmrc`; `engines` stays `>=22.13.0`. A comment cross-references the Dockerfile's `node:22-alpine`.

**CI.** `pnpm lint` runs right after install in the existing job, so it fails fast; `pnpm format:check` joins it in the post-reformat follow-up. The job keeps the name **"Typecheck, test, build"**, the exact required check on both branches; a comment in `ci.yml` says not to rename it.
