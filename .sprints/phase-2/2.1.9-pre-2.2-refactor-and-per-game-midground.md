# Sprint 2.1.9: Pre-2.2 refactor + per-game midground audio

**Phase:** 2
**Status:** Closed
**Closed:** 2026-05-18
**Released:** 2026-05-18 (v2.1.9)
**Blocks:** 2.2 Number Climb — the lifecycle-helper extraction (story 1) and the per-game-mode dispatch ADR (story 3) make 2.2 mechanical; without them, 2.2 would copy-paste the GameScene/AsteroidFieldScene duplication and lock it in three ways.
**Depends on:** 2.1.8 (loading-bar visibility) — closed 2026-05-17 (v2.1.8).
**Estimated effort:** 2 days. Six stories — five refactor + one new asset. The refactors are mostly mechanical lift-and-test; the lifecycle helper (story 1) is the highest-risk piece.

## Summary

After v2.1.8 the codebase has accumulated enough per-game-mode patterns (`GAME_BG_MAP`, `GAME_MUSIC_MAP`, `audioScopeFor`, `loadGameBundle`, `LoadingScene` route) and observer plumbing (`Settings.onImageAsteroidsChange`, `Settings.onGameIdChange`) that adding a third game mode (2.2 Number Climb) would lock in the duplication for good. This sprint pays down that debt FIRST — five small refactors that each shrink the surface 2.2 has to interact with — then bundles in a concrete asset delivery (per-game midground audio for Asteroid Field, which currently uses Alien Shoot's `skittering-1` loop incorrectly).

## Stories

### Story 1: Game-scene lifecycle helper

**Type:** Code (refactor; highest-risk piece)

**Problem:** `GameScene.ts` (~570 lines) and `AsteroidFieldScene.ts` (~600 lines) share ~150 lines of near-identical logic: audio loop start/stop, HUD launch, pause/resume hooks, cleanup, endRound → SessionTotalScore add → GameOver transition, defensive `Settings.setGameId` invariant, telemetry prop building. `RoundController` (extracted in 2.1) handled the question-loop bookkeeping; this story tackles the scene-lifecycle bookkeeping.

**Output:**
- New `src/game/services/GameSceneLifecycle.ts` — composition helper (NOT a base class — avoids Phaser scene-inheritance fragility, matches the `RoundController` precedent).
- Takes `{ scene, gameId, getRoundController, getMathId, getSpeed }` at construction.
- Exposes: `enter()` (called from scene.create — handles HUD launch, music+midground loop start, defensive setGameId, RoundStarted telemetry), `exit()` (cleanup — stop loops, stop Hud/Pause/Settings if active), `endRound()` (SessionTotalScore.add + GameOver transition + RoundEnded telemetry), `pause()` / `resume()` (pauseAllLoops, scene.pause(Hud), GamePaused telemetry).
- Both `GameScene` and `AsteroidFieldScene` consume it. The ~150 lines of duplication per scene drops to ~10 lines of glue.

**Acceptance:**
- Alien Shoot plays identically to v2.1.8 (manual playtest verifies same round flow, same telemetry events fire, same audio loops start/stop, same pause/resume).
- Asteroid Field plays identically.
- `pnpm typecheck` / `pnpm test` / `pnpm build` green.
- Existing 301 tests pass; consider adding a 1-3 test smoke test for the helper itself (pure unit-testable if scene/loops/sceneManager are passed as injectable dependencies).

### Story 2: LoadingScene cruft cleanup

**Type:** Code (small)

**Problem:** After sprint 2.1.8 landed, `GameScene.preload()` and `AsteroidFieldScene.preload()` both still call `loadGameBundle(this, this.gameId)` + `attachLoadingOverlay({ scene: this, caption: '…' })`. LoadingScene now runs first and warms the cache; both calls hit `totalToLoad === 0` and are no-ops. Left in as "direct-entry safety net" but in practice no direct entry exists (only LoadingScene starts game scenes). Two harmless redundant calls now; every future game-scene addition would copy them.

**Output:**
- Remove `loadGameBundle` + `attachLoadingOverlay` calls from `GameScene.preload()` and `AsteroidFieldScene.preload()`. Both `preload` methods either get deleted entirely OR become empty (depending on whether the lifecycle helper from story 1 takes their place).
- Remove unused imports left dangling.

**Acceptance:**
- LoadingScene → game scene transition behaves identically (visible bar first time, instant cache-hit second time).
- `pnpm typecheck` / `pnpm test` / `pnpm build` green.

### Story 3: ADR for per-game-mode dispatch pattern

**Type:** Docs

**Problem:** Six places key off `GameId` (`GAME_BG_MAP`, `GAME_MUSIC_MAP`, `audioScopeFor`, `loadGameBundle`'s scope filter, `LoadingScene` caption switch, `DifficultyScene` scene-key route). The pattern is consistent but uncodified. Adding game #3 is "1-line per place" — clearer if a single ADR documents the contract.

**Output:**
- New `docs/adrs/ADR-NNNN-per-game-mode-dispatch.md` (pick the next ADR number — check `docs/adrs/` for sequence).
- Sections: context (multiple game modes, each with its own assets/bg/music/audio scope); decision (Record<GameId, X> at each dispatch site, central GameId union as the single source of truth); consequences (TypeScript exhaustiveness forces the addition of a new GameId to populate every map; one-line-per-place edit; no consolidation into a single mega-record because each map answers a different question).
- Cross-reference the six places + the `loadGameBundle` signature.
- Include a "How to add a new game mode" checklist a future contributor can follow mechanically.

**Acceptance:**
- ADR exists, follows the project's ADR template style.
- Number Climb's spec (2.2) can reference this ADR for the dispatch pattern.

### Story 4: Settings observable helper

**Type:** Code (refactor)

**Problem:** `Settings.ts` has two near-identical observable fields (`gameId`, `imageAsteroidsEnabled`). Each one duplicates: `Set<Listener>` + per-listener try/catch in the setter + Warning-level telemetry on listener error + unsubscribe-returning subscribe. The third subscriber will arrive with 2.2 (potentially) or 2.3 (likely).

**Output:**
- New `src/services/observable.ts` — `createObservable<T>(name: string)` returns `{ get, set, subscribe }` where `subscribe(listener) => unsubscribe`. `name` is used in the listener-error telemetry payload.
- `Settings.ts` refactored to use it: two fewer Set declarations, two fewer fan-out loops, two fewer try/catch blocks. Behavior identical.
- 3-5 unit tests on the observable helper (subscribe/unsubscribe/multi-listener/listener-throws-doesn't-break-others/idempotent-set).

**Acceptance:**
- All existing Settings consumers (BackgroundScene gameId listener, AsteroidFieldScene imageAsteroids listener) work identically.
- `pnpm typecheck` / `pnpm test` / `pnpm build` green.
- Tests pass; total test count grows by 3-5.

### Story 6: Per-game midground audio

**Type:** Code + asset (asset pre-processed; wiring remains)

**Problem:** Both game scenes currently start `MidgroundKeys.Skittering1` in their `enter()` audio-loop block. `skittering-1` is named for and tuned to Alien Shoot's hero-running-loop feel; the Asteroid Field "asteroids floating in space" mode has zero reason to use it but does so because the wiring was copied unchanged when 2.1 was written.

**Asset pre-processed:** `sfx_midground_spaceNoises_1.mp3` → `public/assets/audio/midground/space-noises-1.mp3`. Encoded with `pnpm audio:encode --kind midground` (which defaults to no-trim for loops). Output: 96 kbps mono, 44.1 kHz, -23.5 dB mean / -6.3 dBTP, metadata stripped, 6.03s loop preserved.

**Output (remaining):**
- `MidgroundKeys.SpaceNoises1: 'space-noises-1'` added to `src/core/audioKeys.ts`.
- New `GAME_MIDGROUND_MAP: Record<GameId, MidgroundKey>` (parallel to `GAME_MUSIC_MAP`). Mapping: `alien-shoot` → `Skittering1`, `asteroid-field` → `SpaceNoises1`.
- `audioScopeFor` extended with a row for `SpaceNoises1` → `'game:asteroid-field'` (the new asset is Asteroid-Field-only, so it loads via `loadGameBundle` not boot).
- Game scenes (via the lifecycle helper from story 1) read their midground key from `GAME_MIDGROUND_MAP[this.gameId]` instead of hard-coding `Skittering1`.
- CREDITS.md: new "Asteroid Field midground" subsection mirroring the loop-3.mp3 entry.

**Acceptance:**
- Alien Shoot still plays `skittering-1` under one-shot SFX (unchanged behavior).
- Asteroid Field plays `space-noises-1` instead.
- Switching between modes mid-session cleanly stops the prior midground + starts the new one (lifecycle helper's enter/exit handles this).
- Cached re-load of Asteroid Field finds `space-noises-1` already loaded (lazy-loaded on first AF entry).
