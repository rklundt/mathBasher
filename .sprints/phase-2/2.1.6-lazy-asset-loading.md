# Sprint 2.1.6: Lazy per-game asset loading

**Phase:** 2
**Status:** Closed
**Closed:** 2026-05-17
**Released:** 2026-05-17 (v2.1.6)
**Blocks:** 2.2 Number Climb (less critical with this sprint in place — boot load stops growing linearly with game count, so 2.2 doesn't need to think about asset budget)
**Depends on:** 2.1.5 (per-game bg + music + session total) — closed 2026-05-17. This sprint reuses the `GAME_BG_MAP` / `GAME_MUSIC_MAP` pattern + the GameId taxonomy.
**Estimated effort:** 2-3 days. Manifest refactor + boot/game-scene migration + loading-overlay extraction + 6-reviewer audit.

## Summary

Today `BootScene.preload` loads **every** asset the game might ever need (~5.5 MB at 128 alien tier, ~7 MB at 192) before the splash dismisses. As 2.2 Number Climb (and future modes) add their own art + music, the boot load grows linearly with game count even though a single play session only touches one mode's assets.

This sprint partitions assets into scopes — `eager` (boot, every session), `always` (boot, every game uses them), and `game:<gameId>` (loaded when that game scene's `preload` runs the first time). Phaser's per-scene preload lifecycle + idempotent texture cache makes the first-time-loads-everything / subsequent-no-ops behavior fall out for free.

Target outcome: boot transfer drops from ~5.5 MB to ~2 MB (~64% reduction at the current 2-game state).

## Open-question answers (decided 2026-05-17)

1. **Music loop scope** — `loop-3` moves to `game:asteroid-field`. 600 KB savings; first-round delay is sub-second.
2. **Asteroid-belt bg** — stays eager. Simpler; 1.1 MB is one-time cost, avoids the BackgroundScene swap race.
3. **Loading-overlay polish** — minimal "Loading… N%". Ship the win; polish later if needed.
4. **Both modes lazy-loaded** — yes. The whole point of the sprint; no half-measure.
5. **Sprint id** — 2.1.6.

## Stories

### Story 1: Manifest refactor — add `scope` field, partition functions

**Type:** Code (no behavior change)

**Output:**
- Add `scope: 'eager' | 'always' | 'game:alien-shoot' | 'game:asteroid-field'` to every entry in `SPRITE_MANIFEST`, `AUDIO_MANIFEST`, and the alien-sprite loop registry.
- Add `bootAssets()` and `gameAssets(gameId)` partition helpers.
- All existing assets initially tagged `'eager'`; partitions added but unused.
- Verify: boot still loads every asset (no behavior change).

**Acceptance:** `pnpm typecheck` / `pnpm test` / `pnpm build` green. Manual playtest: both games play identically to pre-sprint.

### Story 2: Extract `LoadingOverlay` helper

**Type:** Code (refactor)

**Output:**
- `src/game/ui/LoadingOverlay.ts` — render-only helper. Takes a scene + the loader; subscribes to `progress` + `complete` events; renders a thin progress bar + "Loading… N%" label centered on-canvas.
- Skips render entirely when `loader.totalToLoad === 0` (no flicker on cached re-loads).
- BootScene's existing loading bar refactored to use the new helper.

**Acceptance:** BootScene loading bar looks identical to pre-refactor. Helper is callable from any scene's preload.

### Story 3: Memoize sprite-tier choice

**Type:** Code (small)

**Output:**
- `pickSpriteTier()` result cached in a module-scope value (`_cachedTier: SpriteTier | null`) on first call.
- BootScene's first call populates it; per-game preloaders (next stories) read from the cache.

**Acceptance:** No behavior change; same tier picked for the same device.

### Story 4: Add `preload()` to AsteroidFieldScene (validate the pattern)

## Risks

- **Anim cache regression** (story 6) — the most-tested code path is the alien spritesheet animation system. The guard against re-creating anims must be correct; a regression here breaks every Alien Shoot round.
- **Race between BackgroundScene bg-swap and game-scene preload** — kept the asteroid-belt bg eager (open question #2) to sidestep this. If a future story wants to lazy-load the bg too, this race needs addressing.
- **Loader-error UX** (story 8) — first-time-the-user-sees-a-loading-bar is also first-time-they-might-see-a-load-failure. Falling back gracefully matters more here than in any other scene.
