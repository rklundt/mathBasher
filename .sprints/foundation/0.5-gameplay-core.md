# Sprint 0.5: Gameplay Core

**Phase:** Foundation
**Status:** Closed (2026-05-09)
**Blocks:** 0.5.1 Pause + escape, then 0.6 Mobile + responsive
**Depends on:** 0.2 Math engine, 0.3 Score store, 0.4 Scene flow
**Estimated effort:** 1-2 days
**Released:** v0.5.0

## Summary

The actual game. Hero auto-runs along the bottom; four aliens carrying answers descend from the top; player presses Space (or clicks/taps) to fire upward. Hit detection resolves correct / wrong / timeout outcomes. Wrong shot triggers the speed penalty (aliens accelerate). Each round is 20 questions; on completion, transitions to `GameOverScene` with the final score. Still uses placeholder shapes (rectangles, circles, text) — no Kenney art yet (that's 0.7).

## Stories

### Story 1: Hero entity (auto-run)

**Type:** Code
**Output:** `src/game/entities/Hero.ts`
**Acceptance:**
- Class `Hero` extends Phaser.GameObjects.Container (or similar)
- Renders a placeholder shape: a colored rounded rectangle, ~48x64 px
- Auto-runs left-and-right between the canvas left and right safe-area bounds at `config.hero.runSpeedPxPerSec`
- Faces the direction of motion (visual flip is fine; rectangle with a small "front" notch makes it readable)
- Exposes `x`, `y`, `currentLane(lanes: number, leftBound: number, rightBound: number): number` returning which lane the hero is currently under (0..lanes-1)
- Exposes `playHitAnim()` (brief flash) and `playDeathAnim(onComplete: () => void)` (drops/shakes for ~400ms then calls back). No respawn delay required between waves; the next wave starts when the GameScene says so.

### Story 2: Alien entity (descending answer carrier)

**Type:** Code
**Output:** `src/game/entities/Alien.ts`
**Acceptance:**
- Class `Alien` extends Phaser.GameObjects.Container
- Constructor takes `{ scene, x, y, lane, answer, descentSpeedPxPerSec }`
- Renders: a placeholder shape (rounded rectangle ~80x60 px), with the `answer` rendered as large centered text
- Descends linearly at the given speed (updated each frame in `WaveSystem`, not in the entity itself, so the system can adjust speed mid-wave without per-alien state changes)
- Exposes `setDescentSpeed(px: number)` for the wrong-shot penalty boost
- Exposes `playExplodeAnim(correct: boolean, onComplete: () => void)` — short tween + tint flash; correct = green flash, wrong = red flash
- Exposes `lane: number`, `answer: number`, `bottomY: number` getters

### Story 3: Projectile entity

**Type:** Code
**Output:** `src/game/entities/Projectile.ts`
**Acceptance:**
- Simple upward-moving bullet (small rectangle or ellipse)
- Configurable speed (e.g. 800 px/sec; live in `config.hero.projectileSpeedPxPerSec`, add to config)
- Exposes a getter for current Y; killed once it leaves the top of the canvas or on collision
- One projectile alive at a time per `config.hero.fireCooldownMs` (the InputSystem enforces cooldown; the projectile itself doesn't need to know about cooldown)

### Story 4: WaveSystem

**Type:** Code
**Output:** `src/game/systems/WaveSystem.ts`
**Acceptance:**
- Constructor `WaveSystem(scene, { lanes, descentSpeedPxPerSec, penaltyPxPerSec, leftBound, rightBound, topY })`
- `spawnWave(question: Question): Alien[]` — creates 4 aliens, one per lane, each carrying one of `question.choices`. The alien carrying `question.correctAnswer` is recorded internally; helper `isCorrect(alien)` returns true iff that alien is the one created with the correct answer.
- `update(dt: number)` — advances all live aliens. Returns one of: `'in-progress'`, `'reached-hero'` (when any alien crosses below the hero's Y).
- `applyWrongShotPenalty()` — sets every live alien's descentSpeed to `penaltyPxPerSec` for the rest of the wave
- `clearWave()` — destroys all live aliens

### Story 5: HitSystem

**Type:** Code
**Output:** `src/game/systems/HitSystem.ts`
**Acceptance:**
- Pure function-style helpers (or a thin class) that, given a projectile and the live aliens, finds the first alien whose bounds overlap the projectile's current position
- Returns `{ alien: Alien } | null`
- No Phaser physics body required; AABB overlap on rectangles is sufficient

### Story 6: InputSystem

**Type:** Code
**Output:** `src/game/systems/InputSystem.ts`
**Acceptance:**
- Wires up:
  - `Phaser.Input.Keyboard.KeyCodes.SPACE` -> emits `'fire'`
  - Mouse click anywhere on canvas -> emits `'fire'`
  - Touch tap anywhere on canvas -> emits `'fire'` (mobile button comes in 0.6, but tap-to-fire works now)
- Enforces `config.hero.fireCooldownMs` between consecutive fires; rapid-fire is suppressed
- Exposes `onFire(callback: () => void): void`
- Exposes `destroy(): void` to remove handlers when the scene shuts down

### Story 7: GameScene wired to gameplay

**Type:** Code
**Output:** Replace placeholder body of `src/game/scenes/GameScene.ts`
**Acceptance:**
- On `create`:
  - Reads `Settings.round` for `mathId` and `speed`; falls back to a safe default (Add-to-10 / Medium) if anything's null
  - Resolves `generator = getGenerator(mathId)` and `speedConfig = config.scoring.speed[speed]`
  - Instantiates `Hero`, `WaveSystem`, `HitSystem`, `InputSystem`, `ScoreCalculator`
  - Launches `HudScene` parallel
  - Calls `startNextQuestion()`
- `startNextQuestion()`:
  - If question index === `config.round.questionsPerRound`, emits the round-end event and transitions to `GameOverScene` (passing `score`, `correctCount`, `passed`, `stars`, `mathId`, `speed`)
  - Otherwise: `question = generator.generate()`, `wave.spawnWave(question)`, emits `'questionStarted'` with the prompt and choices for the HUD
  - Resets `usedWrongShotThisWave = false`
- `update(time, dt)`:
  - `hero.update(dt)`
  - `wave.update(dt)`; if returns `'reached-hero'`:
    - hero plays death anim
    - calculator records `{ wasCorrect: false, usedWrongShot: usedWrongShotThisWave }`
    - emits `'questionEnded'` to HUD
    - on death anim complete, calls `startNextQuestion()`
  - Updates active projectile's position; if leaves canvas, destroys it
  - On each frame, runs HitSystem against the active projectile and live aliens
- On hit:
  - If correct: alien explodes (green), other aliens are cleared, calculator records `{ wasCorrect: true, usedWrongShot }`, fires `'questionEnded'` event, after explode anim calls `startNextQuestion()`
  - If wrong: alien explodes (red), `wave.applyWrongShotPenalty()`, sets `usedWrongShotThisWave = true`. The wave continues; player fires again.
- On `InputSystem 'fire'`: spawns a projectile at hero's current position, moving upward
- Logs:
  - `RoundStarted` with `gameId`, `mathId`, `speed`
  - `QuestionEnded` with `questionIndex`, `wasCorrect`, `usedWrongShot`
  - `RoundEnded` with `roundScore`, `roundCorrectCount`, `passed`

### Story 8: HudScene wired to events

**Type:** Code
**Output:** Replace placeholder body of `src/game/scenes/HudScene.ts`
**Acceptance:**
- Listens for `GameScene.events`:
  - `'questionStarted'` -> updates the prompt text (e.g. `"7 + 5 = ?"`) and the question counter (`Q: 5/20`)
  - `'questionEnded'` -> updates score display
- Renders:
  - Top-center: prompt
  - Top-left: `Score: <n>`
  - Top-right: `Q: <i>/<total>`
- Style is still placeholder text; visual polish in 0.7

### Story 9: Save score on round end

**Type:** Code
**Output:** Update `GameOverScene.create()`
**Acceptance:**
- The score-store instance is created **ONCE at app boot** (in `src/main.ts`) by calling `createScoreStore()` from `@/services/scoreStoreFactory`. It's then passed into scenes via Phaser's scene-data mechanism (or stored on a tiny module-level singleton accessed by GameScene + GameOverScene). The factory must NOT be called fresh per scene/round — that would create independent in-memory stores and lose all earlier scores.
- **Settings hand-off rule (carryover from sprint 0.4 wrap):** GameOverScene's "Play Again" button calls `scene.start(SceneKeys.Game)` and GameScene re-reads `Settings.round`. If this sprint introduces any `Settings.reset()` call (likely on round end somewhere), make sure "Play Again" still has a valid `mathId`/`speed` to consume — either preserve `Settings` across replay, OR pass `mathId`/`speed` via Phaser scene-data on the `scene.start(...)` call.
- On enter, GameOverScene reads the shared score-store instance and calls `scoreStore.save({ ... })`
- Optionally renders "New high score!" if `bestForCombo` was beaten (read before save)
- Logs `HighScoreSaved` (Information) with `gameId`, `mathId`, `speed`, `roundScore`

## Notes for Claude Code

- This sprint introduces real-time game logic. Resist storing too much state on entities; let WaveSystem/GameScene own the state and let entities stay dumb (just render and play their own anims).
- Phaser Arcade physics is enabled in 0.1 — use it for collision if it's simpler, but a hand-rolled AABB check is fine for this many objects.
- The fire cooldown lives in `config.hero.fireCooldownMs`; do NOT hard-code it in `InputSystem`.
- Death animation duration is short (~400ms). It's there for kid-friendly feedback, not punishment. Don't drag it out.
- Scene shutdown matters: when GameScene exits, it must `this.scene.stop(SceneKeys.Hud)`, and `InputSystem.destroy()` must remove its keyboard/pointer handlers.
- Don't gate on art assets in this sprint. Placeholder rectangles only. Art is 0.7.
