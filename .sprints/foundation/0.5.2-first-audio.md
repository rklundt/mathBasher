# Sprint 0.5.2: First Audio (fire SFX + audio infrastructure)

**Phase:** Foundation
**Status:** Closed (2026-05-09)
**Blocks:** 0.6 Mobile + responsive
**Depends on:** 0.5.1 Pause + Escape, PR #16 (ffmpeg-static dev tooling) — merged
**Estimated effort:** 0.5–1 day
**Released:** v0.5.2

## Summary

mathBasher's first audio. The `fire-1.mp3` SFX plays on every shot. A mute toggle on the HUD lets a kid (or a parent watching a kid play in a quiet room) silence the game in one click; the mute state persists across rounds and page reloads via localStorage. Default volume is moderate (never 100%) so a kid putting on headphones and starting the game doesn't get blasted. iOS Safari's "audio blocked until first user interaction" gotcha is handled by initializing audio on the first Start-button click rather than at boot.

This sprint establishes the audio infrastructure pattern (AudioManager facade, BootScene preload, mute persistence) so future audio work — wrong-shot SFX, round-complete fanfare, music — drops in cleanly.

## Stories

### Story 1: AudioManager refactor

**Type:** Code
**Output:** Update `src/services/AudioManager.ts` (the existing pure-TS facade stub) and create `src/game/services/PhaserAudioManager.ts` (the Phaser-coupled implementation)
**Acceptance:**
- `AudioManager` interface in `src/services/` stays pure TS (no Phaser imports). Exports a small surface: `play(key: string)`, `setMuted(muted: boolean)`, `isMuted()`, `init(scene: unknown)` where `scene` is `unknown` so the pure facade doesn't import Phaser types.
- `PhaserAudioManager` in `src/game/services/` implements the facade against Phaser's WebAudioSoundManager. Holds the scene reference, looks up loaded sounds by key, plays them with the volume-cap honored.
- **Default volume is 0.6** (60%), NEVER 1.0 (per the support reviewer's audio anti-pattern list — "a new sound effect added at full volume 'for impact', impact is achieved through good sound design at moderate volume, not loudness")
- **Mute state lives in localStorage** under key `mathbasher.audio.muted` ("true" / "false"); read at AudioManager construction; written on every `setMuted` call
- **Idempotent init**: `init(scene)` can be called more than once; second call swaps the scene reference but doesn't re-bind anything
- **Defensive on missing keys**: `play('fire-1')` when `fire-1` isn't loaded logs a warning via `_th.logToAi(..., SeverityLevel.Warning, ...)` and returns silently — never throws into the gameplay loop

### Story 2: Asset preload in BootScene

**Type:** Code
**Output:** Update `src/game/scenes/BootScene.ts`
**Acceptance:**
- BootScene's `preload()` loads `public/assets/audio/sfx/fire-1.mp3` under the key `'fire-1'` (also load `fire-2` under `'fire-2'` for future use — it's already shipped)
- Asset key strings come from a constants module, NOT stringly typed at every call site (per the senior-dev anti-pattern: "Asset key strings repeated across scenes (use the constants module)"). Add `src/core/audioKeys.ts` with `AudioKeys.Fire1 = 'fire-1'` etc. Same shape as `sceneKeys.ts`.
- Asset URL paths come from a small helper that prefixes with `/assets/audio/sfx/` so the call site reads `loadSfx('fire-1.mp3')` not the full path
- BootScene logs `BootScene PreloadedSfx` at info with the count loaded

### Story 3: Wire fire SFX to InputSystem

**Type:** Code
**Output:** Update `src/game/scenes/GameScene.ts`
**Acceptance:**
- On `InputSystem` 'fire' event, `AudioManager.play(AudioKeys.Fire1)` is called BEFORE the projectile spawns (so the sound is sample-accurate to the visual fire — no perceived lag)
- Always plays `fire-1` in this sprint. (Variety pick / `fire-2` reserved for a future sprint per the human's direction.)
- Audio plays at the AudioManager's default volume (0.6) — no per-call volume override
- Pause/resume contract from 0.5.1 still holds: when GameScene is paused, fire input is gated, so no audio plays
- AudioManager is instantiated in `GameScene.create()` (or pulled from a module-singleton at app boot, same pattern as scoreStoreFactory). Only ONE AudioManager exists per page lifetime; round-restart does NOT create a new one (would lose the mute state mid-session)

### Story 4: AudioManager singleton + first-interaction init

**Type:** Code
**Output:** New `src/services/audioManagerFactory.ts` (mirrors `scoreStoreFactory.ts`); update `src/main.ts`; update `src/game/scenes/MenuScene.ts`
**Acceptance:**
- `audioManagerFactory.createAudioManager()` is memoized — called once at app boot in `main.ts` (eager init), returns the same instance forever after
- The CONCRETE `PhaserAudioManager` instance is what the factory returns; the type signature exposes the pure `AudioManager` interface so callers can't reach into Phaser specifics
- **iOS Safari guard**: `AudioManager.init(scene)` is called from `MenuScene.create()` (or whatever scene first responds to a user click), NOT from BootScene. Reason: WebAudioContext on iOS Safari needs to be created/resumed inside a user-gesture handler. Calling `play()` before the first user gesture is a silent no-op on iOS. Wiring the init to MenuScene's first-click is the canonical fix.
- A test (Vitest, no phaser import) verifies that the factory returns the same instance on repeated calls — the existing scoreStoreFactory test pattern is the model

## Notes for Claude Code

- **Folder discipline matters here.** `src/services/AudioManager.ts` is the pure-TS interface — no `import Phaser` in there. The Phaser-coupled implementation goes in `src/game/services/PhaserAudioManager.ts`. The factory in `src/services/audioManagerFactory.ts` returns the concrete Phaser impl but exposes the pure facade type. Same pattern as scoreStoreFactory.
- **iOS Safari audio-on-first-interaction is real.** Don't try to `init()` from BootScene; it'll silently fail on iOS Safari and the kid will press fire forever in silence. The `init()` call goes inside MenuScene's first-click handler.
- **Volume cap is a contract, not a default.** `AudioManager.play()` should multiply by the volume cap internally — if a future caller passes `volume: 1.0`, the cap still applies. Don't trust the caller to remember.
- **Mute state is cross-session.** localStorage. Don't store it on a Phaser scene field that gets reset on round restart — that loses the kid's preference between rounds.
- **The Pause flow gates fire input via `InputSystem.setPaused(true)` from 0.5.1.** No audio code change needed for pause to silence sounds; the existing fire-gate naturally suppresses audio because no fire event fires.
- **Don't add a settings screen for audio.** A single mute toggle on HUD is enough for v1. Volume sliders, music vs SFX separation, persistence across browsers — all later sprints. Keep this one tight.
- **For the AudioManager test, check how SessionScoreStore.test.ts handles localStorage** (if at all) — match that pattern for consistency. If the existing tests don't touch localStorage, set up a minimal in-memory mock at the top of the AudioManager test.
