# Sprint 0.5.3: Audio Content Batch + Settings Screen + First Loops

**Phase:** Foundation
**Status:** Closed (2026-05-10)
**Blocks:** 0.5.4 Click-to-start splash + button-click SFX
**Depends on:** 0.5.2 First Audio (AudioManager facade, mute toggle, BootScene preload)
**Estimated effort:** 1.5–2 days
**Released:** v0.5.3

## Summary

Three related additions:

1. **Audio content batch.** Land 5 generated MP3s already produced via the `audio-pipeline` skill — `bloop-1.mp3` (sfx), two `skittering` loops (midground), two `loop-N.mp3` background tracks (music). Plus the encoder gains a third `midground` kind for atmospheric loops.
2. **Settings screen.** First user-facing settings panel. Three stepped volume controls — sfx, midground, music — adjustable in 10% increments from 0% to 100%. Reachable from MenuScene and from the in-round PauseOverlay. Volumes persist to localStorage. The mute toggle (from 0.5.2) becomes a master mute that overrides all three sliders.
3. **First two looping sounds wired to gameplay.** `loop-1.mp3` plays as background music during an active round; `skittering-1.mp3` plays as a continuous loop while the hero is moving (the box's "skittering back and forth" sound). Both stop cleanly when the round ends or the player quits, pause when the game pauses, resume when it resumes. AudioManager grows a small loop API to support this.

After this sprint: a round actually feels like a game — music underneath, hero movement audible, fire still sample-aligned to the visual shot. All three audio kinds (sfx/midground/music) have at least one wired example. Every audio asset shipped today plays at a kid- or parent-controllable volume.

### Story 2: AudioManager per-kind volume + persistence + loop API

**Type:** Code
**Output:** Update `src/services/AudioManager.ts` and `src/game/services/PhaserAudioManager.ts`

**Acceptance:**

Per-kind volume:
- AudioManager exposes per-kind volume API:
  - `getVolume(kind: 'sfx' | 'midground' | 'music'): number` — 0–100 integer percent
  - `setVolume(kind, percent: number): void` — clamps to [0, 100]; persists immediately
- New `AudioKind` type union: `'sfx' | 'midground' | 'music'`
- localStorage keys (one per kind): `mathbasher.audio.volume.sfx`, `.midground`, `.music`. Read at AudioManager construction, written on every `setVolume`.
- **Defaults**: sfx 70, midground 40, music 50. Defaults are exported constants so SettingsScene + tests don't hard-code them.
- `play(key, kind?)` — kind optional for backwards compatibility; defaults to `'sfx'`. Phaser implementation multiplies the played sound's volume by `getVolume(kind) / 100`.
- **Master mute interaction**: when `isMuted()` is true, `play()` is a no-op regardless of slider values (mute wins). Sliders DO NOT auto-set to 0 when muted — they remember their pre-mute values and resume on unmute. (The kid hits unmute and audio comes back at the same levels they had.)
- **Defensive on bad localStorage**: a stored value that doesn't parse to an integer in [0, 100] falls back to the kind's default rather than throwing
- `DEFAULT_VOLUME` constant from 0.5.2 is removed (replaced by the per-kind defaults). Any references in tests are updated.

Loop API (new in this sprint, used by Stories 9+10):
- `playLoop(key, kind): LoopHandle` — starts a looping sound; returns an opaque handle the caller can stop later. Volume tracks the kind's current slider value at start time. Calling `playLoop` for a key that's already looping is a no-op (returns the existing handle).
- `stopLoop(handle): void` — stops a single loop; idempotent.
- `pauseAllLoops(): void` and `resumeAllLoops(): void` — used by GameScene's pause/resume to freeze and unfreeze every active loop in one call.
- **Volume reactivity**: when `setVolume(kind, n)` runs, every active loop of that kind has its volume updated live (so the kid moving the music slider during gameplay hears the change immediately, not after a stop+restart).
- **Master mute affects loops too**: muting drops all active loops to volume 0; unmuting restores them to their kind's slider value. Loops continue playing through mute (they don't restart on unmute) — feels more natural than a hard stop+resume cycle.
- Pure `AudioManager` base class returns a no-op handle from `playLoop` (no engine to drive). `PhaserAudioManager` does the actual work via `scene.sound.play(key, { loop: true, volume: ... })` and tracks the returned `Sound` instances for stop/pause/volume-update.

### Story 3: SettingsScene with three stepped volume controls

**Type:** Code
**Output:** New `src/game/scenes/SettingsScene.ts`; register key in `src/core/sceneKeys.ts`; register scene in `src/main.ts` (between PauseOverlay and AttributionScene so attribution stays on top)

**Acceptance:**
- New scene, launched as parallel (not started), so it can stack on top of MenuScene OR PauseOverlay without tearing them down
- Receives `init({ onBack: () => void })` — caller supplies the close behavior
- Renders three rows, top to bottom: SFX, Midground, Music. Each row:

  - Center: percent text (e.g. "70%") at large font
  - Center-right: `+` button (44×44)
  - Each button click adjusts the kind's volume by **10**, clamped to [0, 100]
  - Disabled state on `−` when value is 0; on `+` when value is 100 (uses PlaceholderButton's existing disabled state)
- Bottom: `Back` button (returns via `onBack`)
- Fully keyboard-navigable via the existing `KeyboardNavigator` with the `Focusable` interface added in 0.5.2 — Tab cycles through −/+/−/+/−/+/Back; Enter/Space activates
- Esc on the scene also calls `onBack` (uses the existing `wireEscBack` helper)
- AudioManager is the source of truth: SettingsScene reads `audio.getVolume(kind)` for initial display and on every adjust; never holds a local mirror

## Notes for Claude Code

- **Don't build a real drag slider.** Stepped `−`/`+` buttons at 10% increments are simpler to build, naturally keyboard-accessible, and easier for kids on touch (no fiddly drag handling).
- **AudioManager is the single source of truth.** SettingsScene must read from `audio.getVolume(kind)` every time it renders — no local mirror that could drift. setVolume → localStorage → next play() picks up the change.
- **The mute-master rule is load-bearing.** It preserves the "kid hits one icon to silence everything" UX from 0.5.2. Don't auto-zero the sliders on mute; just have play() check mute state first.
- **Settings from Pause stacks; from Menu replaces nothing.** Both flows launch SettingsScene as a parallel scene. The difference is what's underneath. SettingsScene knows nothing about its caller — it just calls `onBack` from its init data.
- **Scene registration order matters.** main.ts: ... GameOverScene, PauseOverlay, **SettingsScene**, AttributionScene. Attribution stays on top; Settings stacks above pause but below the §7(b) footer.
- **Backwards-compat for `play(key)` without kind arg.** Existing call (`getAudioManager().play(AudioKeys.Fire1)` in GameScene) should keep working — defaults to sfx kind. We can update GameScene to pass an explicit `'sfx'` for clarity, but it's optional.
- **No new third-party deps.** Stepped buttons use existing `PlaceholderButton`. The percent display is a `Text` object. Phaser handles the rest.
- **Two of the new assets DO get wired this sprint** — `loop-1` as gameplay music (Story 6) and `skittering-1` as the hero movement loop (Story 7). The other three (`bloop-1`, `skittering-2`, `loop-2`) ship as content for future sprints. The split is deliberate: the wired pair establishes the loop API + AudioManager pause/resume integration; the unwired three are queued for whoever designs the broader sound palette.
- **Phaser sound loop lifecycle.** A looping `Phaser.Sound` instance from `scene.sound.play(key, { loop: true })` returns the Sound object. Stopping = `sound.stop()`. Pausing = `sound.pause()`. Resuming = `sound.resume()`. Volume change = `sound.setVolume(v)`. Track these instances in `PhaserAudioManager` so the kind-aware `setVolume` / `pauseAllLoops` / `resumeAllLoops` methods can iterate them.
- **`stopLoop` is idempotent.** GameScene's cleanup may run after the round naturally ended OR after a quit-to-menu — both paths might call `stopLoop` on a handle whose underlying Sound is already stopped. The base AudioManager + the Phaser impl should both treat stop-of-already-stopped as a no-op, not throw.
- **Don't track speed/position in the skittering loop.** v1 is a continuous loop while the hero is alive; no per-direction-change retrigger, no pitch-shift on movement speed. If a future sprint wants the loop to feel position-aware, that's a separate design discussion.
