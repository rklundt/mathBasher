# Sprint 0.1: Scaffold

**Phase:** Foundation
**Status:** Closed
**Closed:** 2026-05-09
**Blocks:** Every other sprint
**Estimated effort:** 0.5 day (actual: ~1 day with the pnpm migration + wrap fixes)

## Summary

Stand up the empty playable shell: Vite + TypeScript + Phaser 3, the folder layout from CLAUDE.md, the central `config.ts`, the telemetry helper with console fallback, an Express server stub for production, and a Phaser BootScene that proves the toolchain runs. No gameplay yet, no menus, no math. Just "it builds, it runs, it loads a Phaser scene."

### Story 8: Express server stub (Azure-ready)

**Type:** Code
**Output:** `server/index.ts`, `server/telemetry.ts`, `server/routes/health.ts`
**Acceptance:**
- `pnpm start` (after `pnpm build`) starts an Express server reading port from `process.env.PORT` (Azure App Service convention), defaulting to `8080` if unset
- **Binds to `0.0.0.0`**, not `localhost` — App Service ingress requires this
- Serves `dist/` as static
- SPA fallback to `dist/index.html` for unmatched routes
- `GET /health` returns `200 { status: 'ok', uptime: <seconds>, version: process.env.BUILD_HASH ?? 'dev' }` in under 100ms (no DB calls, no async work in the handler beyond the `uptime` read)
- `server/telemetry.ts` mirrors the browser-side `_th` shape with cloudRoleName placeholder `'MathBasher.Server'`; reads `process.env.APPINSIGHTS_CONNECTION_STRING` at runtime (does NOT bake it into the bundle)
- Handles SIGTERM and SIGINT gracefully: stops accepting new connections, lets in-flight requests complete with a 30s timeout, then exits 0
- Logs to stdout/stderr only; no file-based log writes
- Logs `serverBoot Started` (with `port`, `nodeVersion`) and `serverBoot Completed` via `_th`

### Story 9: Build scripts and Azure-ready Dockerfile

**Type:** Code
**Output:** `package.json` scripts, `Dockerfile`, `.dockerignore`
**Acceptance:**
- `package.json` scripts: `dev` (Vite), `build` (Vite build), `start` (node server/dist/index.js), `test` (Vitest), `typecheck` (tsc --noEmit)
- `Dockerfile` is multi-stage:
  - **Build stage** uses `node:20-alpine` (or `node:20-slim`); runs `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test`, `pnpm build`
  - **Runtime stage** uses `node:20-alpine` (slim runtime); copies only `dist/`, `server/dist/`, and `package*.json`; runs `pnpm install --frozen-lockfile --omit=dev`; runs `node server/dist/index.js`
  - `EXPOSE 8080` (matches the server's default port)
  - `ENV NODE_ENV=production`
  - `USER node` for non-root runtime (Azure does not require this but it's good hygiene)
  - `HEALTHCHECK CMD wget -qO- http://localhost:8080/health || exit 1` so local `docker run` reports health correctly
- Final image size under 200MB (`docker images mathbasher` to verify)
- `.dockerignore` excludes `node_modules`, `.git`, `.sprints`, `.claude`, `CLAUDE.md`, `docs`, `*.md` at project root except `LICENSE`/`NOTICE`/`README.md`
- `docker build .` succeeds and `docker run -p 8080:8080 mathbasher` serves the page on `http://localhost:8080` (sanity check, not pushed anywhere)
- `docker run` with `PORT=9000` env var listens on 9000 instead — confirms the port-from-env contract
