# Sprint 0.5.1: Pause + Escape

**Phase:** Foundation
**Status:** Closed (2026-05-09)
**Blocks:** 0.6 Mobile + responsive
**Depends on:** 0.5 Gameplay core
**Estimated effort:** 0.5 day
**Released:** v0.5.1

## Summary

Sprint 0.5 shipped real gameplay but no way out of a round once it started. A
kid (or anyone) playing a round currently has to either finish all questions
or close the browser tab to escape. That's a usability and accessibility gap
on its own, and it gets worse on a phone where there's no Esc key at all.

This sprint adds an in-round **pause/escape** flow that works from keyboard,
mouse, and touch. Keyboard nav and on-screen buttons share the same code
path. The pause overlay also gives parents a way to bail their kid out of a
round that's gone sideways without it being a "Game Over."

## Stories

### Story 1: PauseOverlay scene

**Type:** Code
**Output:** `src/game/scenes/PauseOverlay.ts`, registered in `src/main.ts`, key in `src/core/sceneKeys.ts`
**Acceptance:**
- A new parallel scene `PauseOverlay` is registered alongside `HudScene` and `AttributionScene`. It is launched and stopped on demand, NOT persistent.
- When active, it renders:
  - A translucent dark backdrop covering the whole canvas (above GameScene/HudScene, below AttributionScene)
  - A centered "Paused" heading
  - Two `PlaceholderButton`s in vertical stack: **Resume** and **Quit to Menu** (uses the existing button component, so accessibility/contrast/keyboard-nav work out of the box)
  - The same `KeyboardNavigator` pattern used by MenuScene/DifficultyScene so Tab/Enter/Space cycle and activate
- Logs `PauseOverlay Started` / `PauseOverlay Completed` at info level with `from: 'gameplay'` so the App Insights query "where do users pause from" works later

### Story 2: GameScene pause/resume contract

**Type:** Code
**Output:** Update `src/game/scenes/GameScene.ts`, `src/game/systems/WaveSystem.ts`, `src/game/systems/InputSystem.ts`
**Acceptance:**
- GameScene exposes `pause()` and `resume()` methods. `pause()`:
  - Stops the descent timer (`scene.physics` is not in use; pause stops the WaveSystem's tick by setting an internal `paused` flag)
  - Halts the question countdown timer (don't penalize kids for a paused round)
  - Disables InputSystem fire (no shooting from the pause overlay)
  - Pauses any active tween (Phaser `tweens.pauseAll()` scoped to the GameScene)
- `resume()` reverses each of the above. Round state (current question index, score, remaining lives) is preserved exactly.
- WaveSystem's `update(dt)` early-returns when paused, so aliens don't drift while the overlay is up
- HudScene continues to render but is also paused (`scene.scene.pause(SceneKeys.Hud)`) so the question prompt and counter freeze
- A pause that lasts >30 seconds does NOT auto-fail the round — it's not a stealth difficulty mechanic

### Story 3: Esc key + on-screen Pause button

**Type:** Code
**Output:** Update `src/game/scenes/HudScene.ts` (Pause button), update `src/game/scenes/GameScene.ts` (Esc key)
**Acceptance:**
- A small **Pause** icon button is anchored top-right in HudScene. Hit area at least 44x44 device-independent px. Visible during gameplay.
- Esc key in GameScene triggers the same pause flow as the button (one code path through `GameScene.pause()`)
- Pressing Esc *while paused* triggers Resume (round-trip via Esc, no need for the kid to find the overlay button)
- Pause button positioning accounts for AttributionScene footer space and stays clear of the future TouchFireButton position (top-right vs bottom-right doesn't conflict, but document the intent so 0.6 doesn't move the fire button on top of it)

### Story 4: "Quit to Menu" path

**Type:** Code
**Output:** Update `PauseOverlay`, `GameScene`
**Acceptance:**
- Quit to Menu stops `PauseOverlay`, stops `HudScene`, stops `GameScene`, and starts `MenuScene`
- The round is **abandoned**, NOT finished — score is NOT saved (no high-score entry from a quit)
- `_th.logToAi('RoundAbandoned', SeverityLevel.Information, { mathId, speed, questionsCompleted })` fires so abandonment shows up in telemetry separately from a completed round
- No "Are you sure?" confirmation. Quit means quit. The cost of a mis-tap is "play another round," which is fine — and per the support reviewer's anti-patterns list, kid-facing confirmation dialogs are off-limits.

### Story 5: Esc on menu screens (back-stack)

**Type:** Code
**Output:** Update `MenuScene`, `GameSelectScene`, `DifficultyScene`, `GameOverScene`
**Acceptance:**
- Esc on `DifficultyScene` returns to `GameSelectScene`
- Esc on `GameSelectScene` returns to `MenuScene`
- Esc on `MenuScene` is a no-op (top of the stack)
- Esc on `GameOverScene` returns to `MenuScene` (same as the existing "Done" button)
- The handlers live in each scene's `create()` and are registered through `scene.input.keyboard.on('keydown-ESC', ...)`. Clean up in `shutdown` (this is the senior-dev reviewer's listener-leak rule).

### Story 6: Tests

**Type:** Test
**Output:** `src/game/systems/__tests__/WaveSystem.pause.test.ts` (new), updates to existing GameScene tests if any
**Acceptance:**
- WaveSystem: a paused system does not advance alien Y positions on `update(dt)`
- WaveSystem: resume restores motion from the same Y position (no snap, no drift accumulation while paused)
- ScoreCalculator / round state: a paused-then-resumed round produces identical scoring to an uninterrupted round of the same input sequence (deterministic seed + paused frames in the middle)
- These are pure-logic tests; do not import `phaser` (per CLAUDE.md test-layer rule)

## Notes for Claude Code

- **Pause is NOT `scene.scene.pause()` alone.** Phaser's scene-pause stops `update()` but leaves tweens and timers running by default. Tween+timer pausing has to be explicit (`scene.tweens.pauseAll()`, store timer refs and call `.paused = true`). Easy to miss; the senior-dev review will catch it if missed.
- The PauseOverlay scene is **launched** (parallel) on top of GameScene, NOT started in place of it. Starting in place would tear down round state. Use `scene.scene.launch(SceneKeys.PauseOverlay)` and `scene.scene.stop(SceneKeys.PauseOverlay)` to toggle.
- AttributionScene is registered LAST and renders above everything (per its lifecycle comment). PauseOverlay should sit BELOW the attribution footer in z-order so the §7(b) attribution stays readable even when paused. Concretely: launch PauseOverlay before AttributionScene in the scene order, OR set the overlay's depth such that the footer remains on top.
- Keep the Pause button visually distinct from the future TouchFireButton (sprint 0.6). Top-right corner, monochrome icon, no color reuse with the fire button. Sprint 0.7 will polish; this sprint just needs them not to clash.
- The Esc handler on each menu scene is two lines of code, but **forgetting `shutdown` cleanup leaks listeners across scenes** — a kid who navigates Menu → Difficulty → back → Difficulty several times would otherwise stack handlers. Use `scene.input.keyboard.once(...)` if appropriate, or pair `on` with an `off` in `shutdown`.
- `RoundAbandoned` is a deliberately separate telemetry event from a normal round end. Don't fold it into the existing `RoundEnded` schema; abandonment has different downstream meaning (e.g. for "are kids quitting partway through Slow speed at the same question repeatedly?" analysis).
