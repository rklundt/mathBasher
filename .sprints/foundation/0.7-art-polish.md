# Sprint 0.7: Art + Polish

**Phase:** Foundation
**Status:** Closed (2026-05-14)
**Released:** v0.7
**Blocks:** 0.7.5 Mobile + speed tuning
**Depends on:** 0.6.3 Further sprint 0.7 prep

## Summary

Replace remaining placeholder shapes with free CC0 art, layer in modern polish (parallax background, particles, screen shake, tweens, juicy feedback), curate the AI-generated alien sprite pool produced in 0.6.3 down to keepers, and tune typography. Goal: when this sprint closes, a stranger picking up the phone thinks the game looks finished, even though it's the same gameplay loop as 0.5/0.6.

**What changed since this sprint was first planned:** sprints 0.6.1 / 0.6.2 / 0.6.3 did significant prep work (sprite pipeline, asset tiering decisions, in-game animated sprites on falling blocks, loading bar in BootScene, math distribution fix). The story list below reflects what's ACTUALLY left to do — Stories 1, 2, and 4 have all been scope-reduced or reframed; Stories 0, 4a, and 13 are new.

## Stories

### Story 0: Refactor `spriteKeys.ts` to per-kind manifest pattern

**Type:** Code (asset registry refactor)
**Output:** Refactor `src/core/spriteKeys.ts` to support multiple sprite kinds (alien, hero, projectile, ui, particle, bg) following the `audioKeys.ts` pattern.
**Why first:** Architect review of 0.6.3 flagged that the current alien-specific shape (`ALIEN_SPRITE_BATCHES`, `alienSpritePath`, `pickRandomAlienSpriteKey`, `alienAnimKey`) won't scale cleanly when hero/projectile/etc kinds land. If we add hero-loading code before refactoring, that code lands in an alien-shaped module and creates technical debt fast.

**Acceptance:**
- Per-kind key const objects (e.g. `HeroSpriteKeys`, `ProjectileSpriteKeys`) replace the alien-only `ALIEN_SPRITE_KEYS`. Aliens keep their `ALIEN_SPRITE_BATCHES → ALIEN_SPRITE_KEYS` pattern (the grid-based derivation is alien-pipeline-specific and shouldn't bleed elsewhere).
- A `SPRITE_MANIFEST` array (with `kind` field per entry) mirrors `AUDIO_MANIFEST`'s shape — single source of truth for BootScene preload.
- Path helper: `spritePath(kind, key, tier)` replaces `alienSpritePath(key, tier)`.
- Animation key helper: `spriteAnimKey(kind, key)` replaces `alienAnimKey(key)`.
- All existing consumers (`BootScene.preload`, `BootScene.create`, `WaveSystem.spawnWave`) updated to the new shape — no asset-loading regressions, all 45 alien sprites still load + animate.
- Doc-block update on `FRAMES_PER_SPRITE` clarifies it's an alien-extraction default, not a universal constant.
- Typecheck clean; tests green.

### Story 14: Hit feedback SFX (correct + wrong)

**Type:** Code + asset
**Output:** Two short SFX files generated via ElevenLabs and wired into `GameScene.handleHit` alongside the existing particle bursts from Story 4. Surfaced during Story 5 playtest: the visual particle feedback (green burst on correct, red burst + screen shake on wrong) reads cleanly, but adding matching audio would meaningfully sell each event at a body level.

**Acceptance:**
- Two MP3s sourced and committed:
  - `public/assets/audio/sfx/hit-correct.mp3` — bright satisfying chime / ding, ~300-500ms, kid-friendly "you got it!" feel.
  - `public/assets/audio/sfx/hit-wrong.mp3` — brief thud / soft fail tone, ~250-400ms, definitive but NOT a punishing buzzer (no harsh frequencies, no "BZZZT").
- Both LUFS-normalized via `scripts/audio/encode.mjs` `sfx` profile (matches the existing `fire-1`, `button-click-1` levels).
- Two new entries in `src/core/audioKeys.ts` `SfxKeys`:
  - `HitCorrect: 'hit-correct'`
  - `HitWrong: 'hit-wrong'`
- `AUDIO_MANIFEST` auto-picks them up (data-driven derivation — no second edit needed).
- BootScene preloads them automatically through the existing audio loop.
- `GameScene.handleHit` plays the correct/wrong SFX BEFORE the particle burst (audio sample-aligned with visual; Phaser cache makes this zero-latency).
- Mute toggle + per-kind volume slider respected (AudioManager handles this — no GameScene changes for those).
- Existing `WrongShot` telemetry event continues to log; no new telemetry needed for the SFX.

**Process for user:**
1. Generate two SFX via ElevenLabs at the suggested prompts (see Notes below).
2. Drop the raw `.mp3` (or `.wav`) outputs at `.audio-source/raw/sfx/hit-correct.mp3` and `.audio-source/raw/sfx/hit-wrong.mp3`.
3. Tell me they're in place; I'll process them through `pnpm audio:encode --kind sfx --name hit-correct ...` (same recipe as the existing button-click-1), add the SfxKeys entries, and wire into GameScene.

**Notes (ElevenLabs prompt suggestions):**
- Correct: *"Short bright satisfying chime, single positive note resolves quickly, kid-friendly arcade game success sound, no voice, no music, ~400ms duration."*
- Wrong: *"Short soft thud or low fail tone, brief definitive miss sound, NOT a buzzer or harsh annoyance, kid-friendly arcade game wrong-answer feedback, no voice, no music, ~300ms duration."*

The existing `fire-1.mp3` (~280 KB) and `button-click-1.mp3` (~70 KB) are good size references — encode.mjs should bring both new files into similar 50-300 KB range after LUFS normalization.

## Notes for Claude Code

- The line between "polished" and "overdone" is real. A handful of tweens and one screen shake on wrong answers is plenty. Don't chain effects together until the screen is unreadable.
- Animations that happen during gameplay must be SHORT (under 400ms). The kid is waiting for the next question. Slow flourishes belong in menus and game-over.
- If a Kenney pack doesn't have exactly the right sprite, pick the closest one and move on. Custom art is out of scope.
- Don't import any audio files yet. Phase 4 buys/picks them and wires the real implementations. (Note: audio infrastructure WAS landed in 0.5.x; this caveat applies only to new audio assets.)
- After this sprint, the MVP is shippable. Phase 1 (additional math types) is purely additive.
- Story 0 is foundational — do it FIRST. Skipping it means hero/projectile/ui sprite code lands in alien-shaped infrastructure and the tech debt compounds quickly.
- Story 4 + 4a should ship in the same commit so un-credited AI art never enters git history.
