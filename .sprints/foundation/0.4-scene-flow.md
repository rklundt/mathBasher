# Sprint 0.4: Scene Flow

**Phase:** Foundation
**Status:** Closed
**Closed:** 2026-05-09
**Blocks:** 0.5 Gameplay core
**Depends on:** 0.1 Scaffold
**Estimated effort:** 0.5-1 day (actual: ~1 day with the wrap-fix accessibility bundle)

## Summary

Stand up all the Phaser scenes the app needs and wire navigation between them. UI is intentionally placeholder (rectangles, labels, no sprites). When this sprint closes, the user can: open the app -> click Start -> pick "Alien Shoot" -> pick a math type -> pick a speed -> see a placeholder GameScene -> back out to GameOver -> back to menu. Gameplay logic itself is the next sprint.

## Stories

### Story 1: SceneKeys constants and a settings store

**Type:** Code
**Output:** `src/core/sceneKeys.ts`, `src/services/Settings.ts`
**Acceptance:**
- `sceneKeys.ts` exports a const object: `{ Boot, Menu, GameSelect, Difficulty, Game, Hud, GameOver, Attribution }` with string keys
- `Settings.ts` exports a tiny in-memory singleton holding the user's current selection across scenes:
  ```ts
  interface RoundSettings {
    gameId: string;        // 'alien-shoot'
    mathId: MathId | null;
    speed: SpeedKey | null;
  }
  export const Settings = {
    round: { gameId: 'alien-shoot', mathId: null, speed: null } as RoundSettings,
    setMath(id: MathId): void,
    setSpeed(s: SpeedKey): void,
    reset(): void,
  };
  ```
- Logged via `_th` when set (Information, props: `mathId` or `speed`)

### Story 2: Reusable PlaceholderButton helper

**Type:** Code
**Output:** `src/game/ui/PlaceholderButton.ts`
**Acceptance:**

### Story 5: DifficultyScene

**Type:** Code
**Output:** `src/game/scenes/DifficultyScene.ts`
**Acceptance:**
- Two sections: "Math Type" and "Speed"
- Math Type renders one button per entry in `config.scoring.mathDifficulty`. **Tile gating MUST use `getImplementedIds()` from `src/math/registry.ts`** — implemented generators are enabled, stubbed ones are visually disabled with the stub's `description` (`'Coming soon.'`) as the tile copy. A kid clicking a disabled tile must NOT trigger the stub's `throw new Error(...)` — disabled tiles ignore pointer events entirely. Click an enabled tile to set `Settings.round.mathId`.
- Speed renders three buttons: Slow / Medium / Fast. Click sets `Settings.round.speed`.
- A `Start` button is disabled until BOTH a math type and a speed are selected; enabling it transitions to `GameScene`.
- Selected buttons show a clear visual state (border or fill change).
- `Back` returns to `GameSelectScene`.

### Story 8: GameOverScene

**Type:** Code
**Output:** `src/game/scenes/GameOverScene.ts`
**Acceptance:**
- Receives `{ score, correctCount, passed, stars, mathId, speed }` via `init(data)`
- Renders:

### Story 9: AttributionScene — persistent parallel scene (AGPL §7(b) requirement — required, not optional)

**Type:** Code
**Output:** `src/game/scenes/AttributionScene.ts`, key added to `src/core/sceneKeys.ts`
**Acceptance:**
- AttributionScene is a Phaser scene that runs **in parallel** with every other scene EXCEPT BootScene
- BootScene's `create()` (after the brief loading state) calls `this.scene.launch(SceneKeys.Attribution)` BEFORE transitioning to MenuScene
- AttributionScene is registered LAST in the scene array so it renders ON TOP of every other scene
- AttributionScene reads its strings from `src/core/attribution.ts` (created in sprint 0.1) — no string literal duplication
- Renders a footer along the bottom edge of the canvas containing:
  - `mathBasher`
  - `Copyright 2026 Ray Klundt`
  - `Licensed under AGPL-3.0-or-later`
  - `Source: <URL>` — clickable; opens the URL in a new tab on click/tap
- Text is at least 12px at the 1280x720 design canvas, readable, not transparent (alpha >= 0.7), not overlapping interactive UI elements (specifically: not behind the touch fire button area in gameplay; the fire button positioning in 0.6 must respect this)
- Translucent dark backdrop strip behind the text so it stays legible over busy backgrounds (especially during gameplay)
- AttributionScene is **never stopped** during the app lifetime — once launched, it persists until the page unloads
- AttributionScene's input layer is configured so its clickable Source link works even while gameplay scenes are receiving fire input (the Source link's hit area is the only interactive element of this scene; everything else is non-interactive)
- Visual polish (font, exact placement, color matching the menu theme) is a follow-up in sprint 0.7; this sprint just guarantees it's present and legible on all non-Boot scenes
- Cannot be hidden by a user action; cannot be moved to a settings or "Credits" page; no method exists in the codebase to stop or destroy this scene

- [ ] Disabled "soon" tiles are visible and clearly non-clickable
- [ ] AttributionScene runs in parallel with every non-Boot scene; footer is visible and legible on Menu, GameSelect, Difficulty, Hud, and GameOver

- [ ] No method exists in the codebase to stop or destroy AttributionScene at runtime

- [ ] All scenes log `Started` and `Completed`
- [ ] Manual playtest on a desktop browser at 1280x720 shows no overlap or off-canvas elements

## Notes for Claude Code

- Resist the urge to make the placeholder UI look pretty in this sprint. The point is to nail navigation. Art polish is sprint 0.7.
- Use `addPlaceholderButton` for every clickable thing. If it's missing a feature you need (e.g. a disabled state), add it to the helper rather than reinventing per scene.
- `Settings` is a simple module-level singleton, NOT a global event emitter. Scenes read it on `create`. If we ever need reactive updates across scenes, we'll add that intentionally.
- HudScene parallel-launch pattern is the standard Phaser idiom — `this.scene.launch(...)` and listen to events on `this.scene.get(...).events`. Don't try to put HUD inside GameScene.
