**Phase:** Foundation

## Summary

Build the pure-TypeScript math content layer. Defines the `Question` shape and the `QuestionGenerator` interface, ships the first generator (Add to 10), provides shared distractor strategies, registers generators in a lookup table the rest of the app reads from, and unit-tests everything. No Phaser or DOM imports allowed in this sprint's files.

## Stories

### Story 1: Math types

**Type:** Code/data definition
**Output:** `src/math/types.ts`
**Acceptance:**
- Exports:
  ```ts
  export interface Question {
    prompt: string;          // e.g. "7 + 5 = ?"
    correctAnswer: number;
    choices: number[];       // length === config.layout.targetLanes (4), shuffled, includes correct
  }

  export interface QuestionGenerator {
    id: MathId;              // imported from core/config
    label: string;           // human-friendly, used in GameSelect tile
    description: string;     // one-line, used as hover/subtitle
    generate(rng?: () => number): Question;
  }
  ```
- `rng` parameter is optional; when omitted, generators use `Math.random`. Passing an injected RNG enables deterministic tests.

### Story 2: Distractor strategies

**Type:** Code
**Output:** `src/math/distractors.ts`
**Acceptance:**
- Exports `pickDistractors(correct: number, opts: { count: number; min: number; max: number; rng?: () => number }): number[]`
- Returns `count` distinct integers from `[min, max]`, none equal to `correct`
- Throws if the range is too small to satisfy the request (e.g. min===max)
- Exports `shuffleAnswers(correct: number, distractors: number[], rng?: () => number): number[]` that returns a shuffled array containing all values

### Story 3: Add-to-10 generator

**Type:** Code
**Output:** `src/math/generators/addTo10.ts`
**Acceptance:**
- Exports default `QuestionGenerator` with id `'add-to-10'`, label `'Add to 10'`, description `'Two numbers, sum at most 10.'`
- `generate(rng)` produces:
  - Two addends `a, b` in `[0, 10]` such that `a + b <= 10`
  - prompt: `${a} + ${b} = ?`
  - correctAnswer: `a + b`
  - 3 distractors from `[0, 10]`, none equal to correct
  - choices: shuffled length 4
- Distribution: addends uniformly distributed within the constraint (good enough for v1; document if you do anything fancier)

### Story 4: Generator registry

**Type:** Code
**Output:** `src/math/registry.ts`
**Acceptance:**
- Exports `generators: Record<MathId, QuestionGenerator>` keyed by the same `MathId` values as `config.scoring.mathDifficulty`
- For now, only `'add-to-10'` is wired; the other keys (`'add-to-20'`, `'sub-to-10'`, `'sub-to-20'`) are present but throw `Error('Generator not yet implemented: <id>')` from a stub object so the keyspace stays in sync
- Exports `getGenerator(id: MathId): QuestionGenerator` helper

### Story 5: Unit tests

**Type:** Test
**Output:** `src/math/distractors.test.ts`, `src/math/generators/addTo10.test.ts`, `src/math/registry.test.ts`
**Acceptance:** Tests pass via `pnpm test` (Vitest). Coverage of:
- `pickDistractors` returns the requested count, all distinct, none equal to correct, all within range
- `pickDistractors` throws when range is too small
- `addTo10.generate()` (sample 1000 with a seeded RNG):
  - All `a, b` in `[0, 10]`
  - All `a + b <= 10`
  - All `correctAnswer === a + b`
  - All `choices.length === 4`
  - All `choices` include `correctAnswer`
  - All `choices` are integers in `[0, 10]`
- `getGenerator('add-to-10')` returns the addTo10 generator
- `getGenerator('add-to-20')` returns a stub that throws on `.generate()` (verifies the keyspace + the helpful error message)

## Notes for Claude Code

- Pure TS only. If you find yourself wanting to import `phaser`, you're in the wrong folder.
- Don't over-engineer the RNG abstraction. A simple `() => number` parameter is enough for testability.
- Distractors don't need to be "plausible misconceptions" yet (e.g. off-by-one, swapped digits). That's a Phase 1 polish concern. For v1, random valid integers that aren't the correct answer are fine.
- If a generator can't satisfy a request (e.g. weird config), throw a clear error — let the caller decide how to handle it (gameplay should never see a malformed Question).
