# Sprint 0.6.1: Sprite Prep

**Phase:** Foundation
**Status:** Closed (2026-05-10)
**Released:** v0.6.1
**Blocks:** 0.7 Art polish
**Depends on:** 0.6 Mobile + responsive
**Estimated effort:** 0.5–1 day

## Summary

A bridge sprint between 0.6 and 0.7. Builds the **sprite pipeline tooling** that sprint 0.7 (Art polish) needs to ingest raw sprite art at scale — both single-PNG inputs (Kenney CC0 packs) and video-spritesheet inputs (AI-generated alien-grid videos). Mirrors the audio-pipeline pattern from sprints 0.5.2/0.5.3.

Zero game-code changes; this is internal-only tooling. The deliverable is "when sprint 0.7 says 'process the sprites', the pipeline is ready."

## Stories

### Story 1: Single-PNG sprite pipeline

**Type:** Code (toolchain + scripts + workspace)
**Output:**
- `sharp@^0.34.5` added to devDependencies
- `pnpm.onlyBuiltDependencies` allowlist extended
- `scripts/sprites/process.mjs` (~250 LOC) — sharp-based PNG encoder with six per-kind profiles (alien 96px, hero 128px, projectile 32px, ui 256px, particle 64px, bg 512px). Resize within bounding box, palette quantize, strip metadata.
- `scripts/sprites/probe.mjs` (~90 LOC) — image inspector. Reports dimensions, format, alpha-channel transparency, palette status, metadata blocks, file size.
- `pnpm sprite:process` and `pnpm sprite:probe` wired into `package.json`
- `--name <basename>` shorthand on `sprite:process` to derive output paths from `--kind`
- [ADR-0009](../../docs/adrs/ADR-0009-sharp-as-dev-dependency.md) documenting the sharp supply-chain decision (analogue of ADR-0008 for ffmpeg-static)

**Acceptance:**
- `pnpm sprite:process --kind alien input.png output.png` produces a paletted PNG within the alien profile's bounding box, with metadata stripped and alpha preserved
- `pnpm sprite:probe output.png` reports dimensions, palette status, alpha presence, and metadata blocks
- The `pnpm.onlyBuiltDependencies` allowlist gates the sharp postinstall (forcing review for any future package that wants to run code at install time)
- Six per-kind profiles tunable in one place (`PROFILES` const at the top of `process.mjs`)

### Story 4: Video-to-spritesheet extractor

**Type:** Code (~700 LOC)
**Output:**
- `scripts/sprites/extract-from-video.mjs` — ffmpeg + sharp pipeline that takes a video showing a uniform R×C grid of in-place-animating sprites and produces R×C separate WebP spritesheets, one per cell, each with N frames laid out horizontally
- `pnpm sprite:extract` wired into `package.json`
- Supports both `--rows N --cols N` and `--grid RxC` syntax for grid spec
- `--verify-grid` mode: dumps frame 0 with magenta grid lines + yellow margin rectangle to `.sprite-source/working/frame0-grid-RxC.png` and exits, for visual sanity-check before real extract
- Pre-flight ffmpeg probe reports source dimensions, fps, duration; computes effective grid area + per-cell dimensions BEFORE extracting

**Acceptance:**
- `pnpm sprite:extract --rows 5 --cols 6 --verify-grid <video>` produces a verify PNG that lets the human confirm grid alignment before committing to a full extract
- Real extract command produces R×C WebP spritesheets in `public/assets/sprites/<kind>/<prefix>-rRcC.webp` format
- Output WebPs are loadable by Phaser's `load.spritesheet(key, url, { frameWidth, frameHeight })` for animation playback
- Smoke-tested with a 5-second 5×6 alien grid video (30 sprites, 42 frames each at 8 fps, 64×64 cells) — full run completes in under 20 seconds

### Story 5: Background-removal refinements

**Type:** Code (algorithm work inside extract-from-video.mjs)
**Output:** Three iterative improvements to the bg-removal pass, each addressing a specific visual artifact found during smoke-testing:

1. **Flood-fill from cell edges** (replaces simple color-key) — interior bg-colored sprite pixels (e.g. an alien's near-white helmet) stay opaque because the flood can't reach them through the surrounding non-bg sprite body
2. **Auto-margin detection** (`--margin auto`) — scans inward from each video edge to find where the sprite grid actually begins; produces per-side margins (top/right/bottom/left) so asymmetric padding is handled correctly
3. **Soft-alpha** (`--bg-feather N`, default 10) — replaces binary alpha with a smooth ramp through the [tolerance−feather, tolerance+feather] color-distance band; eliminates white halos around anti-aliased sprite edges
4. **Cross-frame consistency restore** (`--consistency N`, default 80) — after per-frame bg removal, restores alpha for pixels that are opaque in ≥ N% of frames but were eaten in some frames by sporadic flood-fill leaks; catches intermittent sprite-clobbering without affecting real animation events

**Acceptance:**
- Auto-margin nails the per-side detection on the smoke-test video (top=32, right=33, bottom=38, left=34) without any manual tuning
- Soft-alpha removes visible halos around dome-helmeted aliens against the dark canvas
- Consistency restore catches helmet-clobbering frames (spotted in r0c0 of smoke-test); 30 cells produce restoration counts ranging from ~500 to >1200 pixels
- The three knobs (`--bg-tolerance`, `--bg-feather`, `--consistency`) interact predictably; SKILL.md V6 has a 3-flag artifact diagnosis matrix

## Notes

- Background removal is now usefully robust but not perfect. Some source videos may need manual `--bg-tolerance` / `--bg-feather` / `--consistency` overrides if they have unusual color ramps or animation styles. The SKILL.md V6 step covers the diagnosis flow.
- The smoke-test extracted 30 alien sprites from `alien-video-1.mp4` to validate the pipeline end-to-end. Those WebPs are NOT shipped in this sprint — they're work-in-progress for sprint 0.7, where the human will curate down to 4–8 keepers and add CREDITS.md attribution before commit.
- Future enhancement candidates (NOT in this sprint, deferred to backlog or future sprints):
  - Color decontamination (subtract bg-color contribution from RGB at partially-transparent edge pixels)
  - Spritesheet/atlas generation (combine multiple processed sprites into a single Phaser-format atlas)
  - Multi-resolution variants (@2x, @3x for HiDPI desktop)
  - Vitest determinism test for the pipeline (gated on a sharp version pin)
