## Summary

A second bridge sprint between 0.6.1 (which built the sprite pipeline) and 0.7 (which uses it). Emerged from a QA session that ran the new pipeline against AI-generated alien videos and discovered that:

1. The default cell size (64×64) was too soft for desktop-tier displays once Phaser FIT scaling stretched the design canvas — needed a tier strategy decision before extracting the production-quality batches.
2. Default frame rate (8 fps) read as stop-motion for organically-animated creatures — needed a bump.
3. Anti-aliased sprite edges left visible white halos when composited over dark game backgrounds — the bg-removal pipeline needed a color decontamination ("unmatting") pass to strip residual bg-tint from partially-transparent edge pixels.

The first two are pure decisions (no code change yet — driven into sprint 0.7 via ADR-0010 + an implementation checklist). The third is a quality fix that landed in the script directly because it had to be in place before re-extracting the production batches.

Zero game-code changes; tooling + decision-capture only.

### Story 2: Color decontamination ("unmatting") in the extract pipeline

**Type:** Code (sprite pipeline quality fix)
**Output:**
- `scripts/sprites/extract-from-video.mjs`: new `decontaminateInPlace()` function (~50 LOC including doc comment) that runs after `removeBackgroundInPlace` to strip residual bg-tint from partially-transparent edge pixels using the inverse Porter-Duff "over" formula `fg = (composite - bg * (1 - α)) / α`.
- Two safeguards: skip α >= 255 (no contamination) and α < 16 (would amplify noise).
- New flag: `--no-decontaminate` to disable (default ON).
- Per-cell progress line reports decontaminated pixel count.
- Status block shows decontamination state.

**Acceptance:**
- [x] White halos significantly reduced on QA against alien-video-1 (preview.html dark-bg test).
- [x] No over-correction artifacts (no weird color shifts at edges).
- [x] Bg-removal % unchanged (algorithm untouched, only RGB of edge pixels modified).
- [x] WebP files ~4-5% larger (decontaminated edges have more varied RGB → less compressible).
- [x] User signed off: "halos reduced, still some pixels, but a lot better. no weird color shifts."

## Lessons

- The sprite-pipeline SKILL's V1 ("ALWAYS ASK GRID SIZE — never infer") caught a real failure mode mid-sprint when batch 2-5 was first attempted with stale grids from before the source videos were swapped. Carrying forward conversational context across replaced source files = bad bet. The SKILL exists for exactly this reason; don't shortcut it.
- Decontamination produces ~4-5% larger WebPs but the visual quality lift is significant on dark backgrounds. Worth it as a default-on pass.
- 12 fps × 2-tier extract takes ~30-60s per batch per tier on this machine. ~5 minutes per source video for full QA cycle. Fine for the sprint-0.7 candidate pool; bears watching if sprint adds more videos.
